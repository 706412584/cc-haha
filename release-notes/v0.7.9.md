# Claude Code Haha v0.7.9

给团队加**共享记忆**：同一项目的所有成员读写同一份记忆（约定、决策、踩坑、测试命令），跨团队会话累积。本地存储、零联网、零服务器。无上游合并。

## 团队共享记忆

**背景**：团队成员每次启动都是一张白纸——上一轮团队踩过的坑、定下的约定、摸清的构建命令，下一轮全部重来。

**现在**：每个项目有一份**共享记忆目录**（位于该项目的自动记忆根下），成员在干活前会先查它，干完会把值得留下的写回去：

- **写什么**：项目级的持久知识——约定、决策、坑与绕法、测试/构建命令、注意事项。不写任务状态（那是任务清单的事），不写密钥或你标记私密的内容。
- **怎么用**：成员的系统提示词里有一段「Shared team memory」，告诉它目录在哪、先查再干、以及怎么维护 `MEMORY.md` 索引。索引会随提示词一起加载。
- **跨会话累积**：同一项目（按 git 仓库根判定，worktree 共享同一份）的后续团队直接受益。

**关闭方式**：环境变量 `CC_HAHA_TEAM_MEMORY=0`；关掉自动记忆（`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`）也会一并关闭。

## 为什么不是直接用上游的团队记忆

上游确实有一套同名系统，但它有三道闸门在本仓库全关：编译期 `TEAMMEM` 开关（未启用）、运行期灰度开关（本仓库收不到）、以及同步链路依赖 Anthropic 账号与 GitHub 仓库。所以那套在这里是死代码，而团队真正需要的更窄——一个项目一份本地记忆目录，不碰服务器。

**真正的缺口**在成员侧：成员的预设是作为**自定义系统提示词**下发的，而记忆提示只存在于默认系统提示词路径里——所以即使目录存在，也不会有任何成员去读写它。本次把这段接上。

## 说明

- **信任边界**：记忆内容由模型写入，且会进入后续成员的系统提示词——成员可以「种」指令给后来的成员。这与既有的自动记忆是同一信任模型（同一台机器、同一用户），但提示词里已明确要求不得写入密钥或私密内容。
- 上游的服务器同步链路保持惰性（本仓库无 OAuth），未来若恢复，两边落在同一个目录约定上。

# Claude Code Haha v0.6.6

修复 v0.6.5（上游 v0.6.3 合并）之后暴露出来的几处回归与中继错误处理问题。

## 恢复工作区丢失的能力

上游重建右侧工作区时删除了旧的面板组件，连带丢掉了三项日常要用的功能：

- **文件列表右键菜单回来了**：文件树重新支持「添加到聊天」「复制路径」「复制绝对路径」和 open-with（IDE / 文件管理器 / 系统默认）。文件和文件夹都可以，引用文件夹会把整棵子树带给对话。键盘上用 `Shift+F10` 或 `ContextMenu` 键打开，`Escape` 关闭并把焦点还给该行。
- **编辑模式的语法高亮修好了**：此前只有 10 种扩展名有语法，其他文件在编辑时整篇是单一颜色（预览却正常——两边用的是不同的高亮器）。现在按扩展名自动加载对应语法，覆盖 Python、Go、Rust、C/C++、Java、PHP、C#、Kotlin、Lua、Ruby、Swift、SQL、CSS、HTML、YAML、TOML、Shell、Dockerfile 等；语言包按需加载，不影响启动速度。无法识别的扩展名仍可正常打开编辑，只是不高亮。
- **markdown 可以编辑了，并且支持边写边看**：此前 markdown 只能只读预览，连编辑按钮都没有。现在和其他文本文件一样可以编辑，并多出一个「分栏」模式——左边写、右边实时渲染。窗口较窄时「分栏」会自动置灰。

## 中继报错不再指错方向

使用第三方 Anthropic 兼容中继时，请求体积超限会被**误报成「此模型不支持图片」**：

- 中继返回的是 `Input content length exceeds threshold`（序列化体积超限），但客户端的错误识别只认 token 相关的措辞，识别失败后落到了「图片被拒绝」的兜底分支——因为对话历史里带着截图。于是界面显示的原因与真实原因完全无关，而且重试永远不会成功（它去剥离图片，但下一轮历史图片照样重发）。现已正确识别这类措辞，交给压缩流程处理。
- **连接失败的诊断信息不再丢失**：此前上游断连时只留下一句「socket connection was closed unexpectedly」，既没有错误码也没有失败的地址，无法判断是服务商故障、本地网络问题还是请求被网关拒绝。现在会带上传输错误码、错误号（仅在有效时）和实际请求的端点。
- 这些诊断信息会写入会话记录与日志，因此做了脱敏：URL 只保留协议、主机与有界的路径，凭据与查询参数不会出现；无法安全解析的地址一律不输出。

## 其他修复

- **工作区根路径可能永久缺失**：文件树在打开任何文件之前就右键时，绝对路径相关的操作会退化成相对路径。现在文件树会自行加载工作区状态。
- **`trace-capture` 偶发把整个检查判红**：追踪写入是「发后不管」的诊断设施，当它的写入目标在排队期间被移除（会话关闭、测试临时目录清理）时会抛出未处理的异常，导致整个服务端检查失败——即使所有用例都通过。现在这类失败被静默丢弃，与诊断服务的既有处理一致。
- **macOS Swift 检查的假红**：macOS runner 偶发把临时目录重挂为只读，导致清理临时目录时抛 `EROFS`，把 17/17 全绿的 job 判红。清理改为尽力而为，测试结果保持权威。

## 说明

- **LSP 在正式版默认关闭**：语言服务器能力由 `CLAUDE_CODE_LSP` 环境变量控制（开发模式默认开，正式版需设为 `1`/`true`/`yes`/`on`）。未开启时文件头的状态胶囊会显示「语言服务器不可用」，编辑与保存不受影响。
- **markdown 现在会进入编辑缓冲链路**：切到编辑或分栏后，未保存的改动会保留在缓冲里，切回预览不会丢失；保存仍走原有的原子写入接口。

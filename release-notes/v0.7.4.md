# Claude Code Haha v0.7.4

本次是三个修复/改进的合集：会话历史里**后台任务通知吞掉后续对话**的严重问题、**团队状态条串会话**、以及 H5 公网隧道**零安装 + 自动切换线路**。无上游合并。

## 会话历史：后台任务通知不再吞掉后续对话

`<task-notification>` 是**回合中途**注入的一条合成记录，不是新回合的开始——助手收到它、回一句「收到」、然后继续干活。但历史投影把它当成回合边界，把它之后的**所有**记录一路压制到下一个真实用户输入为止：助手的文字、`tool_use`、`tool_result`、思考过程统统不见。

后果是：会话记录越活跃，被吞掉的越多。在一份真实 2875 条记录的会话上，旧规则吞掉 **431 条**（跨 5 个窗口，其中一个窗口长达 14 分钟），最后一条幸存的助手气泡成了可见末尾——重开会话看起来就像对话**跳回了旧消息**。

现在压制在**第一条带工具调用的助手记录**处结束（也就是「收到」结束、被打断的工作恢复的地方），原有的「下一个真实用户输入」释放条件保留。同一份记录上恢复了 431 条中的 416 条；只剩通知本身和它的「思考 + 文字」确认被隐藏，这正是设计意图。

服务端 `entriesToMessages`、历史分页投影、子代理运行查找、恢复快照，以及桌面端 `chatStore` 的 UI 映射五处同步修正，避免历史页与恢复快照对同一段记录给出不一致的结果。

## 团队状态条不再串会话

旧的 `TeamStatusBar` 读全局 `activeTeam` 单例，于是在一个会话里启动的团队，会在**其它每个会话**的输入区都渲染一张卡片，而且领队被过滤掉后显示 `0/0` 成员；切换标签页也没有任何东西清空 `activeTeam`。

上游早已用会话级的 `AgentTeamsStrip` 取代它——后者读 `workbenchesBySession[activeTabId]`，当前会话没有团队时什么都不渲染。此前一次合并恢复了旧组件以解 CI 阻塞，导致两条路径同时存活、旧路径仍不受会话约束。本次按上游做法删掉旧路径：组件、测试和只服务于它的两个翻译键一并移除。

## H5 公网隧道：零安装 cloudflared + Pinggy 自动兜底

以前点「一键公网隧道」，机器上没有 cloudflared 就直接失败，而且只有一条通往公网的路——在 trycloudflare.com 不稳的网络上这很要命。本次并入 dsh-desktop 的两项能力：

- **零安装 cloudflared**：从带版本号的缓存目录解析固定版本（2026.9.3），首次使用时下载并做 sha256 校验。Windows ARM64 复用 amd64 构建（Cloudflare 只发布这一个产物）。下载遵循 `HTTPS_PROXY`，连接层失败会重试。darwin 的两个摘要以**实际提供的字节**为准，而不是 release notes（后者对这两个产物是过期的）。
- **自动切换线路**：优先 Cloudflare；任何失败（二进制缺失、下载失败、启动失败、30 秒内没拿到 URL、提前退出）都透明地回退到走系统 ssh 客户端的 Pinggy。只有两条路都失败，隧道才报聚合错误 `Cloudflare: …; Pinggy: …`。命名隧道仍只走 Cloudflare，因为域名绑在那里。

设置页新增线路徽标、由宿主 `onProgress` 驱动的确定性下载进度条、可操作的失败提示，以及「切换线路」手动入口——用于「桌面能打开 Cloudflare URL、但手机上打不开」的情况。

隧道的 `provider` 会同步到服务端，`/api/h5-access` 据此上报；纯状态心跳不会清掉已上报的 provider。

## 说明

- 本次 Windows 应用与安装包**未签名**（SignPath 尚未开通）；macOS 安装包**未签名未公证**，随包提供 `install-macos-unsigned.sh`，首次启动需手动放行。
- 隧道的 Pinggy 兜底需要系统 ssh 客户端；Windows 上取 `System32\OpenSSH\ssh.exe`，首次使用会在缓存目录生成一枚专用 ed25519 身份密钥。

# Claude Code Haha v0.5.42

> 本版本优化普通模式、协调模式和 Agent Tool 的编排策略，降低不必要的子代理调用与独立验证开销，同时保留 Solo Pipeline 的固定计划、测试和人工审批流程。

本说明面向 `v0.5.42` 最终用户与发布维护者。正式安装包仍须从最终 reviewed merge SHA 的干净 worktree 构建，并在发布前完成 package smoke、冷启动和所选发布门禁。

## Highlights

- **风险驱动的编排**：任务步骤数、文件数或工具调用数不再单独触发委派；只有独立上下文、独立审查或真正并行能够抵消协调成本时才使用子代理。
- **主 Agent 决定验证深度**：始终检查最终 diff 是否存在越界改动或残留；除此之外，简单、局部、低风险修改通常可以在 LSP diagnostics、类型检查或最轻量静态检查无误后结束，不再要求每个小功能机械运行 focused test。
- **移除计数型验证提醒**：不再因为第 3 次 Edit/Write/NotebookEdit，或因为 3 个 todo/task 全部完成，就额外插入 focused-check/verification 提醒；edit 数、task 数和文件数都不作为验证证据。
- **按需运行行为测试**：当修改可观察行为且存在便宜、相关的测试时，主 Agent 或实现 worker 根据风险决定是否运行最窄测试。
- **独立验证必须显式授权**：verification Agent 不再是默认收尾步骤，高风险、复杂 bug、PR-ready、文件数或任务数都不能自行触发；只有用户明确要求独立验证时才允许启动。
- **协调模式降低 fan-out**：普通命令、普通测试、轻量检查、同文件顺序修改和定向查找不再因开启协调模式自动外包。
- **Solo Pipeline 保持隔离**：Solo 继续保留 A/B/C Plan Gate、独立 TEST stage、Review HUMAN GATE 和 Land stage；普通模式与协调模式不会继承这套固定流水线。
- **Spark2 UI 质量保证补强**：新增直接 GameUI 视觉设计技能、确定性 UI snapshot 几何审计、像素回归契约、多分辨率缩放矩阵、NineSlice 双重验证，以及共享按钮和面板资源治理。

## 验证策略

### 简单、局部、低风险修改

主 Agent 根据改动性质选择最低成本且足够的检查：

- LSP diagnostics；
- TypeScript 或语言级类型检查；
- 最轻量的相关静态检查；
- 如果没有可观察行为变化，可以不额外运行行为测试。

### 行为变化

如果存在便宜且直接覆盖修改行为的测试，主 Agent 或实现 worker 可以运行最窄相关测试。测试深度由风险、成本和证据价值共同决定，不按功能数量机械累计。

### 独立 verification Agent

只有用户明确要求“独立验证、复核或第二视角”时，才允许启动 verification Agent。以下情况本身都不构成授权：

- 用户只反馈了 bug；
- 复杂 bug 或仍有未解决的不确定性；
- auth、payments、persistence、provider/runtime、infrastructure 等高风险或跨边界改动；
- 广泛重构；
- 准备声明 PR-ready 或 push-ready；
- 文件多、task 多、编辑次数多或实现已经完成。

上述场景中的复现、测试和常规验证均由主 Agent 或实现 worker 完成。主 Agent 可以建议用户追加独立验证，但必须等用户明确同意后才能启动 verification Agent。如果批准的任务或计划没有验证步骤，结束时不得临时追加验证任务。用户显式开启 Solo Pipeline 是唯一模式级例外，因为这等于选择了包含独立 TEST stage 的固定流程。

## 模式行为

### 普通模式

- 主 Agent 保持对理解、实现和验证深度决策的所有权。
- 不为简单 lookup、本地编辑、普通测试或轻量检查启动子代理。
- 后台 Agent 只用于真正独立的并行工作，并且不会阻塞主 Agent 继续处理可执行任务。

### 协调模式

- 文件变更仍遵循协调模式既有 worker 边界。
- 默认使用一个范围明确的 worker；只有文件所有权不重叠且任务互不依赖时才并行。
- 实现 worker 执行与改动相称的本地检查；只有用户明确授权时才增加独立 verifier，不再把它作为固定第二层 QA。

### Solo Pipeline

Solo 是用户显式启用的固定流水线，本版本不改变其五阶段契约：

```text
PLAN GATE → IMPLEMENT → TEST → REVIEW → LAND
```

A/B/C Council、独立 TEST specialist 和两个人工审批 Gate 均保持不变。

## 兼容性与范围

- 不改变 Agent Tool 执行器、后台任务生命周期、worker 调度 API 或 verification Agent 的实际检查实现。
- 不改变 coordinator/Solo 模式开关、WebSocket 互斥逻辑或会话持久化格式。
- 不改变根 `package.json` 的本地 CLI 版本 `999.0.0-local`；Electron Desktop 的权威版本已更新为 `0.5.42`。
- Spark2 插件、插件目录和 UI snapshot 审计器改动已纳入本版本；本地 SQLite MCP 数据库仍不纳入。

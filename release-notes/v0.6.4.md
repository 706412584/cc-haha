# Claude Code Haha v0.6.4

本次更新聚焦**桌面端实测中卡住的两类问题**：新加 MCP 服务器要重启才生效，以及中继流挂起时界面长时间无响应。

## 新功能

- **新增 MCP 服务器立即生效，无需重启 IDE**。此前添加 MCP 服务器后，当前会话要等 IDE 重启才会加载它的工具；MCP 列表的刷新按钮对运行中的会话也没有作用（列表变了，CLI 仍用启动时的配置）。现在添加完成后会立刻把新服务器注入所有已打开的标签页（以及发起操作的当前会话），下一轮对话即可使用其工具。其他项目的会话由既有的项目校验自动跳过；之后再新开的对话本来就会在启动时从磁盘读取配置，天然覆盖。
- **刷新按钮作为兜底恢复路径**。若某个会话错过了注入（例如它在服务器添加之前就已启动），点击刷新会重连该服务器并把同一份注入消息扇出到打开中的会话，无需重启。

## 修复

- **修复思考流挂起时长时间无响应**。部分 OpenAI 兼容中继会持续输出思考内容却始终不给结束标记（实测单次响应超过 25 万个内容增量），而空闲看门狗会被每一个数据块重置、永远无法触发，只能等 600 秒的总时长上限才释放，用户白等十分钟才看到失败。现新增**思考阶段专属上限**（默认 300 秒，可在服务商环境变量中覆盖）：当一次流已经进入思考、却始终没有产出任何正文或工具调用、也没有收到结束标记时提前终止。判定同时覆盖只有签名增量、或直接以加密思考块开头的中继形态——这类流的思考计数恒为零，仅看计数会漏掉。合法的长思考不受影响：一旦出现正文或工具调用，该保护立即失效。
- **修复压缩上下文卡在「思考中」**。压缩的 5 分钟上限此前只是一个中止信号，当中继持续推送数据、不理会该信号时，压缩请求会一直停留在读取循环里，收尾逻辑永远不执行，界面就卡在「思考中」直到 600 秒上限触发（若看门狗被关闭则可能一直卡住）。现在 5 分钟同时作为硬性截止时间，无论上游是否响应中止信号，压缩都会在限定时间内结束并给出结果。
- 定时器清理统一收口，避免时长上限在异常退出路径上残留并误伤后续请求。

## 说明

- 压缩失败时界面会短暂显示「思考中」后回到空闲，并且不会出现「已手动压缩」分隔线——因为压缩确实没有成功。这是预期行为。

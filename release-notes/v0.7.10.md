# Claude Code Haha v0.7.10

两个修复：**团队状态条隐藏后找不回来**，以及 **H5 隧道断线后不会自动恢复**。无上游合并。

## 团队：隐藏之后可以再显示

之前把团队状态条隐藏掉（点条上的 ×，或用团队卡片上的「隐藏」），它就再也回不来了——界面上没有任何恢复入口。原因是隐藏状态记在一个模块内的集合里，只有「隐藏」和「是否隐藏」两个动作，**没有「显示」**，而且只在整份状态被重置时才会清空。

现在：

- 隐藏后，原来的位置会留一个**「显示团队状态」**的小按钮，点一下就恢复。
- 隐藏状态仍按**会话 + 团队**分别记录：在一个标签页隐藏，不影响其他标签页；换了新团队也照常显示。

## H5 隧道：断线自动重连

之前隧道进程意外退出（最典型的是 **Pinggy 免费线路 60 分钟到期**）只会把状态标成「错误」并停在那里，公网地址变成死链，要你自己重新点一次。

现在：

- 隧道意外退出会**自动重连**（最多 3 次，间隔 1s / 3s / 8s），成功后用新地址重新上报；连续失败才落到错误状态。
- 设置页在重连期间显示**「正在重连」**，并保留线路提供方，让你知道是哪条线路断了。
- **Pinggy 线路会提示 60 分钟上限**——免费隧道到时必然断开，断线后可切换到 Cloudflare 或重新启动。
- 重连期间「停止隧道」按钮依然可用：**手动停止不会被自动重连复活**。

另外修了一个健康检查的健壮性问题：检查公网地址时改走系统代理（此前用 Node 内置 fetch，不读 `HTTP_PROXY`）。在需要代理才能访问外网的机器上，旧检查会一直超时；现在经代理探测，代理不可达时按「不确定」处理，不会误判隧道已死。

## 验证

- 新增/改写测试：隧道重连往返、重连预算耗尽后落到错误态、**停止后不被复活**（变异验证：移除守卫即红）；团队隐藏→显示往返（并断言真的触发了重渲染，而非只改了内部集合）；设置页的 Pinggy 上限提示、重连态、以及「重连时按钮是停止而非重启」。
- 本机实测（真实 FlClash 机器）：`import('undici')` 从 `desktop/` 解析成功；`ProxyAgent` 经代理桥访问公网 200，而全局 fetch 对需代理的域名全部超时——确认修复方向正确。
- 桌面与服务端 `tsc` 均通过；CI 全绿（含覆盖率门禁，改动行覆盖率 96.97%）。
- 独立子代理审核两轮，其中隧道重连的「停止后复活」竞态由审核发现并已修复。

## 说明

- 健康检查走代理属**健壮性提升**：本机当前是系统代理模式，隧道边缘地址恰好可直连，所以它不是此前「隧道打不开」的成因；真正的成因是 Pinggy 的 60 分钟上限与「退出不重连」，这两项本次已修。
- 自动重连由单元测试覆盖；真机杀进程的端到端验证建议自行复现一次（起隧道 → 结束 `cloudflared.exe` → 设置页应显示「正在重连」并自动恢复）。

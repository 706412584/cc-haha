# Code Council v0.5.54

> 本版本修复超大会话记录导致的 CPU 异常占用：轮询路径不再重复整文件解析，单个超大 transcript 也不再让整个本地索引失效。

## 重点更新

### 轮询路径不再整文件重解析

- 会话签名比对（1500ms 轮询）改为对父 transcript 与各 subagent 文件做 `stat`，用 `(mtimeMs, size)` 拼身份串，不再流式读完整个文件。488MB 会话原本单次约 1.6 秒，超过轮询间隔，会持续占满一个核心。
- Inspection 快照与会话列表摘要改为按字节偏移续算。两者的累加器在追加写文件上都是单调的（求和、min/max、last-wins、Map upsert），因此续算结果与整文件重解析一致。
- 实测 119MB transcript：列表摘要冷扫 898ms → 续算 1ms。
- 写入中途的半行不计入续算偏移，下次扫描待其写完后重读；文件被改短或改写时丢弃缓存并重新全量折叠。

### 超大 transcript 不再拖垮整个索引

- `source-too-large` 由“协调失败”改为“单源限制”，不再计入 `degradedSources`、不再把索引整体置为 `degraded`，其余会话照常索引。限制仍通过 `lastErrorCode` 可见。
- 超过 `SESSION_INDEX_MAX_SOURCE_BYTES` 的 transcript 改为按上限索引前缀而非整体拒绝，`indexedBytes` 停在最后一个完整行边界，未读部分记为 pending tail，会话因此仍可被列出与搜索。
- 启动时按错误码区分持久化的降级行，限制类不再被提升为整轮扫描失败码。

### 会话列表排序正确性

- `building` 期不再直接采信残缺索引页。索引发现只在每 25 个文件的批次内部按 mtime 排序、项目目录按 readdir 顺序遍历，因此 building 期的索引行是任意子集，第一页可能漏掉真正更新的会话。
- 改为用磁盘上的 transcript 数做覆盖率交叉校验，覆盖不全则回退文件扫描；覆盖齐全时即使仍在 building 也照常读索引。校验只读目录不读文件，实测约 6ms。
- 修正续算时的排序回落：无可解析时间戳的 transcript 会回落到 stat mtime，续算命中时需刷新该值，否则侧边栏按过期时间排序。

## 已知限制

- 已达大小上限的 transcript 无法再推进前缀，会长期停留在 `pending`：可列出、可搜索，但最新消息不进索引。仅提高上限不会触发重读（未变更文件会判定为 `unchanged`），需要 parser 版本变更或重建。

## 验证

- `bun run check:server`：325 个文件、3679 项测试全部通过。
- localIndex 全目录与会话索引一致性回归：279 项通过。
- 新增定向用例断言「续算结果 === 冷解析结果」，覆盖写入中途半行、文件改短后重新折叠、以及超大源产出可用的部分投影。
- 修复过程中发现并修正一处真实回归：末行缺少换行时记录丢失，导致新建会话 inspection 返回 404。

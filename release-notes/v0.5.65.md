# Code Council v0.5.65

> 修复长会话记录反复全量解析导致的界面顿卡，并给流式重试加上墙钟预算，避免慢速上游把重试拖成数分钟静默。

## 修复

### 大会话记录反复全量解析导致界面顿卡
会话记录（`sessionId.jsonl`）的解析缓存此前对超过 16 MiB 的文件直接跳过缓存，每次读取都要重新读盘 + 全量解析。活跃会话的记录通常正好落在 16–50 MiB 区间，于是每次侧栏刷新、workbench 轮询都会把 20–27 MiB 的文件整体重解析一遍——单次同步解析可达约 1.5 秒，表现为界面卡顿。诊断数据显示 3 小时内累计重读约 23.5 GB、约 1100 次全量解析，全部集中在两个大文件且缓存命中率为 0。

现在凡是被完整读入的文件都进缓存（超过 50 MiB 上限的会走 tail 分支，是唯一不缓存的情况）；内存仍由缓存总量上限（64 MiB）加 LRU 淘汰兜底。

### 流式重试静默过长：改为墙钟预算而非纯次数
瞬时流式错误的重试此前只按次数封顶（默认 4 次）。对快速失败的瞬断（如 socket reset，1–2 次近乎瞬时的重发即恢复）这没问题；但当上游先接受请求、随后挂起约 30 秒才返回空流时，「4 次重试」会被拖成约 2 分 40 秒的纯静默——用户全程只看到「连接中断，正在重试」的横幅。

新增墙钟预算 `CLAUDE_STREAM_TRANSIENT_RETRY_BUDGET_MS`（默认 60 秒），与次数上限并存，谁先到达就停止；退避等待也会被裁剪到剩余预算内，不再把时间浪费在一次马上就要放弃的等待上。设为 `0` 可恢复旧的纯次数行为。

## 其它并入本版的改动
- 工具输出中的图片渲染：支持远程 `previewUrl` 直出、丢弃与远程图重复的本地兄弟路径以消除破损重复图块、识别 source 嵌套的 MCP 图片块（如布局预览截图）。
- 切换进空闲的虚拟化会话后重新吸底，避免停在基于估算高度的旧位置。
- 单图预览预留高度，减少转录区闪动。

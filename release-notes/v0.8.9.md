## 本版修复

- **大会话把所有会话卡死**：打开轮次很多的会话后，其他会话发消息没反应、不报错、加载历史要十几秒。根因是轮次变更卡片（`turn-checkpoints`）每次轮询都用 Myers 行 diff 重算每个改动文件的增删行数；一个大文件整体换行符变化（LF→CRLF）就让单个文件 diff 跑 15 秒，阻塞 server 事件循环 30–70 秒。现在改动超过 1000 处时改用线性计数。实测 243MB 会话从 67.7s 降到 4.3s，50MB 会话从 37.1s 降到 3.9s。工作区状态的增删行统计同样受益。
- **合并回归（冲突解决时 fork 侧覆盖了上游修复）**：
  - `chatStore`：`api_retry` 的 `requestId`、Token 用量按 usageKey 取最大值去重、团队邮箱投影的 `modelContent`。
  - `ws/handler`：标题生成改为 await + 取消守卫，避免 CLI 启动时扫到空转录。
  - `traceCapture`：路径被占用时 `recordCall` 正确 reject，未处理拒绝改在 fire-and-forget 调用点兜住。
  - `compact`：直调方能观察到调用方自己的 abort 信号。
  - 图片请求：provider 有卸载 endpoint 时跳过本地 12MB 裁剪，否则超大图到不了 DeepSeek files API。
- **手机 App 下载与关于页链接**指向 fork 仓库 `706412584/cc-haha`。

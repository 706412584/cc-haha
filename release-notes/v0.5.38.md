# Claude Code Haha v0.5.38

> 本版本提升 Desktop 一键公网隧道与 CLI 长会话可靠性，修复最大推理强度传递和媒体生成结果展示问题，并同步上游 `v0.4.8` 的桌面工作流、Provider 兼容性与安全加固。

本说明面向最终用户与发布维护者。桌面端版本号保持为 `0.5.38`；媒体与推理修复通过 PR #101 合入，CLI timeout 与验证策略修复通过 PR #102 合入。本次继续把上游 Git tag `v0.4.8` 合并到项目的 `v0.5.38` 发行轴；当前尚未创建 tag 或发布 GitHub Release。

## Highlights

- **Quick Tunnel 假在线修复**：当 `cloudflared` 意外退出时，Desktop 会立即清除旧 tunnel URL、停止展示失效公网地址，并将状态切换为明确的错误态。
- **HTTP 524 健康监控**：Quick Tunnel 启动后会通过公网 `/health` 检查真实可达性；连续 3 次收到非 2xx 响应（包括 Cloudflare `524`）后，Desktop 会停止失效进程并清理服务端 tunnel override。
- **避免代理环境误判**：主进程网络异常只会等待下次检查，不会直接关闭 tunnel；只有实际收到非 2xx HTTP 响应才累计失败，避免系统代理或 PAC 配置差异造成误杀。
- **重启竞态保护**：旧 tunnel 的延迟健康检查、网络响应或进程退出事件不会覆盖后来启动的新 tunnel URL 和运行状态。
- **设置页状态同步**：H5 Access 设置页仅在 tunnel 处于 `starting` 或 `running` 时每 10 秒刷新 diagnostics；进入 `error` 后停止轮询并保留错误信息。
- **最大推理强度生效**：选择“最大”后，Anthropic-compatible 请求会正确传递最高推理档位；经兼容网关转换到支持的 OpenAI 模型时可映射为 `XHigh`，不再回落到 `Medium`。
- **媒体生成图片内联显示**：media-gen 内置 Agent 生成的图片会直接显示在 Agent 结果卡片中，无需展开文本或手动打开输出链接；普通 Agent 返回的 URL 不会被误识别为生成图片。
- **减少不必要的验证 Agent 调用**：小型、局部改动由主 Agent 直接执行 focused tests 和 diff 检查；只有复杂、高风险、跨边界、明确审查或 PR-ready 工作才使用独立 verification Agent。
- **CLI timeout 恢复**：Desktop 的任务轮询与工具刷新会按 session 共享同一个在途请求，避免 1 秒轮询叠加耗尽 Electron 连接池；兼容网关返回零事件 SSE 时会在尚未产生输出或工具副作用的边界内安全重试一次。
- **任务周期竞态保护**：session 切换、clear、reset 和 TodoWrite 使用 generation 隔离旧响应；清理 completed list 时由 Server 在锁内比较完整任务快照，只删除仍匹配的旧周期，不会误删随后出现的新任务。
- **同步上游 `v0.4.8`**：吸收 Grok 官方 OAuth、Claude Code Auto 权限模式、对话导航、推理强度滑杆、内联 Diff 评审、Windows 升级数据恢复、本地服务鉴权、远程预览隔离、诊断脱敏与浏览器受限端口规避。
- **可选统一 Activity 面板**：通用设置新增“统一活动面板”开关，默认继续使用 `SessionTaskBar`、`TeamStatusBar` 和 `BackgroundTasksBar`；开启后改用上游 Activity rail 集中查看 Tasks、Team、Background Tasks 与 Subagents，同时保留 coordinator、Solo Pipeline、handoff chips 和 `SoloCouncilPanel`。Desktop 打开 Workspace 时会暂时隐藏 rail，关闭 Workspace 后恢复原打开状态；移动布局使用 overlay。
- **Spark2 UI 导出真实闭环**：内置 `spark2-gamedev` 插件升级到 `1.0.1`，新增第 12 个技能，指导 Agent 用真实双端编译、AppBundle 部署、Runtime MCP、全页面截图和资源格式检查验收 C# UI 导出。

## 推理强度与媒体结果

- 推理强度与扩展思考字段现在独立处理；Anthropic Messages 使用 `output_config.effort=max`，不会因 `thinking.type` 的取值而丢失用户选择的推理档位。
- 第三方模型仅在 provider 明确声明支持时发送对应推理参数，未声明能力的模型仍保持安全降级。
- IDE 会按顺序完整累积上游 SSE 的所有 `thinking_delta`。兼容网关是否返回 reasoning summary 由上游及网关策略决定；当前实测网关固定请求 `reasoning.summary=auto`，不由 Anthropic 请求中的 `thinking.type` 控制。
- media-gen Agent 的 Markdown 图片和输出 URL 会去重后内联展示，并继续支持点击预览与后续图片操作。

## Agent 验证策略

- 主 Agent 对自己报告完成的工作负责，必须先直接运行相关测试并检查 diff。
- Todo 数量、Task 数量和文件编辑次数继续提供一次性提醒，但仅作为弱风险信号，不会再机械要求启动 verification Agent。
- 独立 verification Agent 保留用于复杂 bug、高风险或跨边界修改、大范围重构、明确审查请求、仍有实质疑问以及 PR-ready 验证。
- Agent 工具示例和 Agent 生成器不再把“写过代码”自动映射为 test-runner 调用。

## Desktop Quick Tunnel

### 公网可达性检查

Quick Tunnel 成功建立后，Desktop 会检查公开地址的 `/health`：

- 首次检查会等待 tunnel 建立稳定后再执行。
- 健康响应会清零连续失败计数，单次或间歇性异常不会关闭 tunnel。
- 连续 3 次明确的非 2xx 响应会判定当前 Quick Tunnel 已不可用。
- 判定失联后，Desktop 会停止对应 `cloudflared`、清除旧公网 URL，再向服务端写入错误状态。
- 不会自动重启 Quick Tunnel，避免随机公网 URL 静默变化导致现有二维码和书签指向旧地址；用户可在设置页手动重新开启。

### 生命周期与状态清理

- `cloudflared` 非预期退出时不再只更新状态，而是显式清除服务端保存的 runtime tunnel URL。
- 用户主动停止或重新启动 tunnel 时，会清理旧健康检查 timer 和失败计数。
- generation 与当前 child 双重校验会隔离旧异步回调，避免旧 tunnel 清除新 tunnel 的 URL。
- Named Tunnel 未启用同样的强制健康判定，因为 Cloudflare Access、WAF 或自定义路径可能正常返回 401/403 等响应。

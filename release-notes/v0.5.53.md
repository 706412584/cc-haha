# Code Council v0.5.53

> 本版本修复 Grok 最大推理档位、计划批准后的权限恢复、path-only 图片批注与会话标签滚动稳定性问题。

## 重点更新

### Grok 最大推理档位

- 修复 Provider 主模型与重复模型槽位共用模型名、但该槽位未声明 capability 时丢失主模型 capability 的问题。
- 自定义 Grok 主模型现在会正确发送 `output_config.effort=max`，不再由兼容接口回落到默认 Medium。
- 保留会话内 Provider 切换与 thinking 不兼容时的清理行为。

### 计划权限跨重启恢复

- 进入 plan mode 时持久化进入前的用户权限模式。
- sidecar 或 Desktop 重启并恢复会话后，批准 `ExitPlanMode` 会恢复原权限，不再错误回落到“询问权限”。
- 退出 plan mode 后清除旧的恢复元数据，并为异步批准失败返回可重试错误，而不是产生未处理 Promise rejection。

### 图片批注

- composer prefill 现在保留 path-only 图片路径。
- `ChatInput` 与 `EmptySession` 统一通过既有本地文件端点解析批注图片来源，修复打开批注后原图黑屏。
- 文件访问继续沿用绝对路径、图片类型、允许根目录、realpath 与文件大小安全边界。

### 会话标签稳定性

- 用户通过滚轮或触控板接管标签条后，不再被 active-tab 自动对齐反复拉回。
- overflow 生命周期内稳定保留左右滚动按钮槽位，避免切换对话并点击“继续”后滚动区域宽度抖动。

## 版本

- Electron Desktop：`0.5.53`
- 根 CLI 版本保持 `999.0.0-local`

## 验证

- PR Quality 的 Desktop、Server、Provider、Chat Contract、Policy 与 Coverage 门禁全部通过。
- 服务端定向回归 362 项通过，Desktop 两处图片批注入口 72 项通过。
- 脱敏真实 HTTP 转发抓包确认 Grok 请求包含 `output_config.effort=max`。
- 权限恢复与本地文件访问安全审查通过，无越权、权限提升或路径逃逸发现。
- 最终发布资产将由 reviewed release commit 在全平台 release workflow 中重新构建并验证。

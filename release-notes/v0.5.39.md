# Claude Code Haha v0.5.39

> 本版本新增 Desktop Agent Office：保留原版像素办公室、PixiJS / Spine 角色、工位拜访、气泡与表情互动，并直接映射 cc-haha 的真实 Main Agent、Team、SubAgent、Background Agent 与 Task 状态。

本说明面向最终用户与发布维护者。Desktop 版本号更新为 `0.5.39`；Agent Office 仅在 Desktop 运行时按需加载，不改变 Android / H5 的默认界面和首屏运行路径。

## Highlights

- **原版 Agent Office 视觉接入**：保留办公室背景、桌椅素材、六个 Chibi Spine 角色、四向移动、工位遮挡与动态深度排序；ai-office-react MIT notice、Spine Runtimes License 与 Chibi 示例素材许可均随对应资产一起打包。Chibi 图片仅获非商业再分发许可，因此本版本不得用于商业分发或商业用途。
- **真实 Agent 状态映射**：Office 直接消费现有 chat、CLI task、team、background task 与 Activity stores，不增加第二套任务生命周期，也不新增 HTTP polling。
- **拟人化岗位编排**：Main Agent 以“老板”身份出现；真实 Team、SubAgent、Background Agent 与 Task 分别映射为团队成员、研发专员、运维专员和项目专员，并进入稳定的六席位视图。
- **可中断的人格与趣味事件**：空闲或等待中的员工会低频闲聊、追剧或打游戏；工作或思考中的员工也会主动展示认真、思考、灵感等人格表情，并仅以极低概率出现趣味事件。空闲/人格类事件属于场景瞬时状态，真实任务状态或任务文本变化会立即抢占；用户主动发起的进行中拜访仍按自身生命周期完成。
- **保留趣味交互**：点击人物可选择拜访其他工位或播放 Spine 表情；原版会伪造“开始工作/空闲”的手动状态按钮已移除，避免覆盖真实运行状态。
- **默认大弹窗，可切独立 tab**：顶部 Agent Office 入口默认打开大尺寸 modal；通用设置可改为独立 tab，modal 也可一键展开。
- **Office tab 单实例与返回路径**：同一 session 使用 `__office__${sessionId}`，不会重复打开；独立 tab 提供“返回会话”按钮，Office tab 不写入持久化标签列表。
- **GPU 生命周期隔离**：modal 展开为 tab 时先卸载旧 Pixi / Spine canvas，再创建新实例，避免同一 session 短暂存在两个 WebGL renderer。
- **Desktop-only lazy load**：PixiJS、Spine runtime 与 Office scene 保持在独立 `AgentOfficeRuntime` chunk 中；普通聊天和移动 H5 不加载该运行时。
- **实时信息去噪**：席位和右侧“当前任务流”不再混入 Earlier tasks；近期失败仅保留五分钟关注窗口，后台命令使用可读标题并去除重复详情，完成历史只用于统计。
- **稳定员工生命周期**：相同 `sourceKey` 保持原工位；活动结束后员工先进入 90 秒 retained idle，再释放座席，避免实时更新导致人物闪烁或频繁换位。
- **主题与五语言适配**：React chrome 与 Pixi floor、标签、气泡共同跟随 white、light、eyeCare、dark 和 system 主题；Office 状态、handoff 与交互文案支持英文、简中、繁中、日文和韩文。
- **可操作的真实工作台**：人物和任务卡使用稳定来源键双向高亮；可打开 SubAgent 运行记录、团队成员会话、停止后台任务、定位输出文件和忽略失败项，不提供伪造任务状态的按钮。
- **任务依赖与负责人**：Office 展示 Task 的 `owner`、`blockedBy`、`blocks` 和编排元数据；named Agent 只通过 Agent name 与 Task owner 精确关联，不按标题或描述猜测归属。
- **真实任务调度**：未阻塞 Task 可立即交给 Main；Main 忙碌时进入现有 message queue。支持稳定排序后的多选调度、队列立即发送/移除和 stale 标记，Renderer 不直接创建 Agent，也不预先伪造 `in_progress` 状态。
- **成员消息**：可从 Office 向真实 TeamMember 发送短消息，并与“让 Main 调度 Task”操作明确区分。
- **响应式与无障碍**：窄屏使用纵向布局与两列统计；提供键盘可达的 DOM roster、`aria-pressed` 状态和可见交互提示。
- **完整 reduced-motion**：动态响应系统偏好，停止 Spine 时间轴、环境事件、自动/手动拜访和装饰动画，同时保留真实任务状态、位置与标签更新。
- **本地路径安全**：输出文件仅在文件管理器中定位；Windows UNC、混合分隔符、设备 namespace 和远程 `file:` URL 会在任何文件系统访问前被拒绝。
- **克制但可并行的 Agent 编排**：Main Agent 默认负责理解、关键路径实现和聚焦验证；只有至少两条未阻塞、无需彼此结果且文件 scope 不重叠的执行线才进行并行 kickoff。复杂计划使用 Task DAG、owner、wave、execution、file scope 和 verification 元数据；启动 named background Agents 的同一轮，Main 继续自己的实际工具动作。小任务、同文件任务和链式依赖不 fan-out，Coordinator mode 仍保持纯协调。
- **本地 Provider 协议说明与鉴权修复**：设置页明确区分 Anthropic 原生协议与 OpenAI Chat / Responses 本地协议转换；转换由 cc-haha 本机完成。吸收上游 v0.4.9 后，Desktop 受控 Claude CLI 在 H5 关闭时仍可通过本地 OpenAI proxy 正常鉴权。
- **Provider 保存响应优化**：编辑服务商成功后直接更新本地列表，不再等待重复的 Provider / Settings 全量刷新；保存失败会显示明确提示，避免按钮长时间停留在加载状态。
- **微信会话失效恢复**：WeChat 收到 `-14 session timeout` 后停止当前轮询并释放 typing controller；Desktop 显示重新扫码提示，重绑仅更新登录凭据并保留配对、白名单和默认工作目录。
- **运行时日志去噪**：CLI `keep_alive` 现在静默处理，不再产生 unknown message 日志。

## 数据与交互边界

- Main Agent 状态按真实活动派生：前台 chat/tool 优先，其次是监督运行中的 SubAgent、运行中的 background command、未阻塞 pending Task、全部 blocked 的 pending Task，最后才是空闲。
- Team、SubAgent、Background Agent、CLI Task 和目标 session 的 message queue 复用统一 `SessionActivityModel` 分类和状态语义。
- 六个 Pixi entity ID 保持稳定；真实活动只替换席位姓名、状态、任务和 source key，避免动态 Agent ID 触发 WebGL 对象树重建。
- 场景层只拥有位置、路径、拜访、气泡、表情和低频趣味事件等瞬时动画状态；任务状态仍以现有 Zustand stores 为唯一权威来源。
- Activity snapshot 更新不会中断进行中的拜访；动画完成后恢复到最新真实状态。

## 展示方式

- 默认：在当前会话上打开大尺寸 Agent Office modal。
- 设置：`设置 → 通用 → Agent Office` 可切换为独立标签页。
- modal 中可使用“展开为标签页”；旧 canvas 会先销毁。
- Office 独立 tab 可使用“返回会话”回到来源 session，并关闭自身。

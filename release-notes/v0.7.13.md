# Claude Code Haha v0.7.13

两个用户当日实测反馈的修复：OpenAI 网关 400 拒绝所有请求、H5 手机端加号菜单弹不出来。无上游合并。

## OpenAI chat 网关不再拒绝 adaptive thinking

**背景**：接入 unisound（u2-flash）等 OpenAI chat 格式的网关后，**每条消息都立刻 400**：`'thinking.type' must be one of: enabled, disabled`，会话完全不可用。

**根因**：CLI 对未知模型按通用 profile 声明了 `adaptive_thinking` 能力，请求携带 `thinking: {type: "adaptive"}`——这在 Anthropic 协议里合法；但 openai_chat 转换层把 `type` 原样透传，只认 `enabled/disabled` 的网关直接拒绝，且 400 不可重试，所以每轮必现。

**修复**：转换层把 `adaptive` 重写为 `enabled` 再透传——模型仍然自己决定思考多少，`reasoning_effort` 继续控制深度；`enabled/disabled` 原样保留。附带两个回归测试，并由独立子代理确认 openai_responses 路径不透传该字段、全仓唯一调用点无行为退化。

**顺带实测澄清**：u2 系列返回的 "does not support image_url" 是**上游服务端能力**（直连 curl 复核），该系列没有开放视觉输入——发图请换支持视觉的 provider，这不是本地 bug。

## H5 手机端：加号菜单不再被裁成灰色小块

**背景**：手机浏览器里点对话编辑框的 **＋**，不弹菜单，工具栏上只出现一块灰色小方块。

**根因**：H5 专属样式给工具栏左侧容器加了 `overflow-x: auto`（窄屏横滑），而加号菜单是从这个 44px 高的容器**向上弹出**的绝对定位面板——被裁剪得只剩一条碎片，看起来就是盖在权限图标上的灰块。桌面浏览器不加载这条 H5 规则，所以只在手机上复现（模拟触屏视口复现确认）。

**修复**：菜单打开时给编辑框 shell 标记 `data-capability-menu-open`，H5 样式在该状态下放开裁剪；菜单关闭即恢复横滑。已用移动模拟验证菜单完整弹出、关闭后滑动保留，并在既有移动端测试中固化该标记的开关断言。

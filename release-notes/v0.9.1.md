# Claude Code Haha v0.9.1

dogfood v0.9.0 过程中发现的五个问题的修复版。无新特性，全部是缺陷修复与诊断增强。

## 修复

- **会话模型被静默换掉**（`e55e08eba`）：stale-modelId guard 比对模型槽位时漏了 `fable` 槽——选在 Fable 槽的模型（如 `GLM-5.3[1m]`）每次启动都被误判为「模型已删除」，静默替换成 main 槽模型并持久化；且回退值丢了 `[1m]` 标记，后续协作操作报 `SESSION_MODEL_UNAVAILABLE`（「会话模型不可用」）。现在 guard 覆盖全部五个槽位，回退值保持 catalog 身份。
- **中转站 403 client_not_allowed**（`e4bbf81f7`、`acdfce2f3`）：relay 此前把 `claude-cli/...` User-Agent 当内部头剥离；且 OpenAI Chat / OpenAI Responses / Gemini 三条跨协议路径从空对象构造上游头，出站 UA 退化为 `Bun/x.y.z`。现在四条路径统一透传客户端身份（Anthropic 专有头与 `x-stainless-*` 在跨协议时仍丢弃，凭据与 framing 始终排除，preset 的 `upstreamHeaders` 仍可覆盖）。星驰等按客户端白名单放行的站点应恢复正常。
- **自定义请求头保存后回退**（`2c3c2e962`、`ebe42b009`）：provider 编辑器的「自定义请求头」此前只写共享 settings.json，非活跃 provider 保存即丢；第一轮修复又漏了服务层（`buildSavedProvider` / `updateProvider` 逐字段构造记录时没复制 `customHeaders`），每个 provider 的头现在真正落盘（null 清空、省略不变）。
- **「此电脑不支持当前操作」误报**（`9c803f904`）：防止休眠的能力检测是启动时一次性快照，探测一次失败就永久显示不可用。现在 PowerShell 探测失败时回退解析 `powercfg /a`（中英文输出都支持），并在每次显示「不可用」前按需重探。
- **H5 隧道入口收敛**（`912e10172`）：隐藏不稳定的 Cloudflare quick tunnel 一键入口，默认命名隧道（已运行的 quick tunnel 仍可停止）；Tunnel Token 输入框旁新增「验证格式」按钮（本地解码 + `{a,t,s}` 校验，零副作用）。

## 诊断增强

- 隧道启动链路（`dd1757504`）：`startTunnel` → provider 尝试 → 二进制 / token 解析全程记录到 `diagnostics/electron-host.log`，卡死无反应时不再盲查。

## 其他

- `docs/FORK_CUSTOMIZATIONS.md` 登记跨协议 UA 透传与 stale-modelId guard 两条定制，防上游合并回归。
- 测试：proxy 205、websocket-handler 205、providers 244、generalSettings 154 全绿；CI 19/19 pass。

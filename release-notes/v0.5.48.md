# Claude Code Haha v0.5.48

> 本版本修复两类运行时卡死/报错：**停止后 `SESSION_TURN_ACTIVE` 锁死**（无法再发消息），以及 **跨 Provider 会话内切换** 时把 Grok 等 encrypted thinking / signature 带入 GPT 等上游导致的 `encrypted content could not be verified` 400。**不**强制空白新会话；保持 in-session Provider 切换。

## 问题背景

1. **停止后无法再发**  
   用户点「停止」后桌面立刻 idle，但服务端 turn lock 原先主要依赖 CLI `result` 释放。若 CLI 无/迟到 `result`，`activeUserTurns` / coordinator 仍占用 → 下一条 `user_message` 被拒：`SESSION_TURN_ACTIVE`。

2. **Grok → GPT（或其它第三方）同会话 400**  
   历史 assistant 消息里的 `thinking` / `redacted_thinking` / signature 在跨 Provider 请求时不可验证。旧路径只在 ant model-fallback 等场景 strip；运行时 third-party 边界未统一 sanitize。

## 行为变更

### A. 停止立即释放 turn lock

1. `handleStopGeneration` 在设 `sessionStopRequested` / interrupt 的同时：  
   - 有 `activeUserTurns` 条目 → `clearActiveUserTurn`  
   - 否则 → `sessionActivityCoordinator.endUserTurn`
2. UI idle 与服务端锁一致，停止后可立刻再发。
3. Force-kill（3s）门控改为：仍在 stop 请求中 **且** 会话上 **没有** 新 turn 时才 `stopSessionInstance`，避免误杀替换回合。

### B. 第三方 API 边界 strip thinking / signature

1. `queryModel` 在 `normalizeMessagesForAPI` 之后：若 `hasAnthropicCompatibleThirdPartyConfig()`（非 firstParty 或非官方 `ANTHROPIC_BASE_URL`），对消息做 `stripSignatureBlocks`。
2. 可见文本历史保留；不可验证的 thinking / redacted_thinking / connector 签名块在发往上游前剥离。
3. **不**因 Provider 切换强制 fork 空白会话（见 in-session 兼容策略）。

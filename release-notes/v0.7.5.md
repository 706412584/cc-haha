# Claude Code Haha v0.7.5

本次是两个修复：**团队跑起来后停不掉、解散不掉、藏不掉**，以及 **Cloudflare 隧道抖动后状态不会自动恢复**。无上游合并。

## 团队：可以停止、解散和隐藏了

之前团队一旦启动，界面上就找不到任何收尾手段。排查后确认不只是缺按钮——服务端有两个缺陷让团队**永远清不掉**：

- **停止运行中的团队，状态永远停在「运行中」**。停止逻辑只处理「启动中」的计划，运行中的直接被跳过。于是 worker 已经停了，界面还一直显示团队在跑，计划也永远清不掉。
- **团队无法删除**。删除要求「领队已停止且没有其他成员」，但成员退出后只是被标记为「已终止」，**从不从配置里移除**，领队的活动标记也从不复位——这个条件永远无法满足，而界面上又没有手动移除成员的入口。

现在：

- **停止**：运行中的团队也能停，状态正确落到「已中断」。
- **解散**：停止后（或本来就未运行时）可一键解散——先停 worker，再注销成员，最后删除团队目录。
- **隐藏**：顶部团队状态条新增隐藏按钮。隐藏按「会话 + 团队代次」区分，**只影响当前标签页**，同名的新团队不会被连带隐藏。

另外，团队卡片在运行中时**不再整卡消失**——之前那唯一的停止按钮恰好在你最需要它的时候不渲染。

## 隧道：抖动后自动恢复，不再误杀

cloudflared 与 Cloudflare 边缘节点断连后会**自己重连**（实测约 50 秒恢复，进程不退、地址不变）。但健康检查把「连续 3 次探测失败」当成终态：**杀掉进程、清掉地址、置为错误，且没有任何路径回到正常**。后果是一次它已经自愈的抖动，会让应用一直显示「隧道不可用」，而那个地址其实已经恢复服务——你只能手动重启隧道，而快速模式重启会换新地址，等于链接作废。

现在探测结果是一个**状态**而不是一次拆除：

- 探测成功 → 自动从错误恢复为运行中，并重新上报地址。
- 探测失败 → 降级为错误，但**进程保留、继续探测**，下一次成功即恢复。
- **只有已经成功服务过请求的地址才允许被判为故障**；从未成功过的探测失败不再改变状态——客户端探测失败不能当作隧道故障的证据。

## 说明

- 本次 Windows 应用与安装包**未签名**（SignPath 尚未开通）；macOS 安装包**未签名未公证**，随包提供 `install-macos-unsigned.sh`，首次启动需手动放行。
- 隧道的 Pinggy 兜底是免费版：**连接 60 分钟被服务端强制断开，且重连后地址会变**。需要固定地址请用命名模式（自有域名 + Cloudflare 隧道 token）。
- 「隐藏团队状态」是会话内的临时视图状态，切走或重开即恢复。

# Code Council v0.9.4

补丁版本：修复 Provider「测试连接」与「获取模型」不携带自定义请求头，导致按客户端身份做白名单的网关（agentrouter、xingchiapi 等）对探测返回假 401。包含 v0.9.3 全部内容。

## 修复

- **探针携带 `customHeaders`**（`7ffad125f`）：测试连接与获取模型都直连上游、不经过本地 proxy，此前只发送凭据和预设头。agentrouter 这类网关按 User-Agent 白名单放行，proxy 路径会透传 CLI 标识（真实聊天正常），但探测用的是默认 UA，于是返回 `401 unauthorized client detected` —— 用户看到"测试连接失败"而误判 provider 不可用。
  - `parseCustomHeaderLines` 按 CLI 侧 `ANTHROPIC_CUSTOM_HEADERS` 的语义解析多行 `Name: Value` 文本（首冒号分隔、坏行跳过、重复行后者胜）。
  - 测试连接：preset 声明头打底、用户自定义头覆盖（大小写不敏感替换，避免同名头被 `Headers` 合并成 `"a, b"`），再经 `resolveUpstreamHeaders` 剥除 `Authorization` / `x-api-key` 等凭据类头。
  - 获取模型（上游 `/v1/models` 探测与候选端点探测两条路径）：用户头先应用、凭据最后写，保证凭据永远不被 `customHeaders` 替换。
  - 桌面端表单的测试与获取模型按钮都带上当前 `customHeaders`；`savedConfigUnchanged` 判断纳入该字段，改动后不再复用旧 provider 的值。
  - `docs/FORK_CUSTOMIZATIONS.md` B 节已登记，防上游合并回归。

## 验证

- 真实上游（agentrouter.org `/v1/messages` + `gpt-6.1-sol`）：带 `user-agent: codex_cli_rs/...` → HTTP 200；不带 → HTTP 401 `unauthorized client detected`。
- 服务端新增 12 例：`upstreamHeaders.test.ts`（解析 6 例）、`providerService.test.ts`（探针透传、空白头省略、用户覆盖 preset、凭据不可替换 4 例）、`providerModelCatalog.test.ts`（透传、凭据优先 2 例）。
- 相关回归：服务端 `providers.test` + `concurrent` + `runtime-env` 282 例、桌面 `ProviderSettings`/`Proxy`/`generalSettings`/`api/providers` 242 例全过；桌面 `tsc -b` 通过。

## 配置提示

若使用 agentrouter 这类白名单网关，推荐：

```
baseUrl:       https://agentrouter.org/v1
apiFormat:     anthropic（原生 Messages，最少转换层）
模型：          gpt-6.1-sol（服务端实际 id，无分组前缀）
鉴权：          Bearer Token (auth_token)
customHeaders: user-agent: codex_cli_rs/0.20.0 (external; cli)
```

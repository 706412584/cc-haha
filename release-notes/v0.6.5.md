# Claude Code Haha v0.6.5

本次更新合并上游 **Claude Code v0.6.3**（30 个提交），并在此基础上把 fork 自有的**内联编辑器与 LSP** 重新移植进上游重建后的工作区架构。

## 上游 v0.6.3：右侧工作区整体重建

上游把右侧面板从「模式切换」重写成了**统一标签控制器**：文件、浏览器、评审、终端四种标签共用一个面板，可以自由拖拽换位、移动停靠边（侧边 / 底部）、固定或预览，面板隐藏时标签和后台进程都保留。同时新增：

- **公网访问管理**（Public Access）：配对凭据、自动启动、同意版本管理，替代了原先的一次性隧道入口。
- **模型设置改版**：原「服务商」页更名为「模型设置」，文案与字段命名随之调整（服务商 → 模型配置）。
- **Composer 引用菜单**：文件搜索菜单升级为统一的引用菜单，插件与技能分组展示。
- **上下文用量会话统计**、**冻结回合检查点**（turn checkpoints 支持 `frozen` 查询）。
- **连接器（Connectors）**：扩展市场拆出独立的连接器页面与目录。

## fork 自有功能：重新移植

上游重建工作区时删掉了 fork 的编辑缓冲 store 与面板组件，但**内联编辑器与 LSP 的能力本身仍然保留**——本次把它们接回了新架构，而不是恢复旧的面板：

- **编辑 / 预览切换**：文本文件标签默认只读预览（可引用行、加行注释到对话），点「编辑」切换到 CodeMirror 6 编辑器。两种模式共用同一份 `sessionId::path` 身份，来回切换不丢改动、不重新拉取文件。
- **保存与冲突**：走原子写入接口保存，保留编码（UTF-8 / BOM）与行尾（LF / CRLF / CR）探测；磁盘内容被外部改动时弹出冲突横幅，提供「重新加载 / 保留我的 / 打开冲突视图」。
- **未保存改动拦截**：关闭有改动的文件会弹确认框（放弃 / 保存 / 取消），保存中不可关闭，超时保留缓冲并提示。
- **LSP 状态与诊断**：文件头显示语言服务器状态胶囊（就绪 / 启动中 / 不可用 / N 个错误），下拉列出诊断并按文件分组，点诊断跳转到对应位置；缺失前置条件时提供安装入口，其他失败可一键重启。
- **Agent 编辑感知**：Agent 通过工具写入某个已打开的文件时，该文件的编辑器会标记为 agent 来源的冲突，提醒你重新加载。
- **不支持编码降级**：非 UTF-8 系编码的文件自动回落到只读预览，并给出说明。

## 修复

- **`classic-dark` 主题终端配色对比度不足**：上游把 ANSI 调色板拆成了明暗两套斜坡，而 fork 独有的 `classic-dark` 主题不在上游视野里，导致它回落到明亮斜坡——终端红/绿/蓝在 `#0E0E0E` 上对比度只有约 2.9:1，几乎不可读。现为该主题补上独立的深色 ANSI 覆盖块。
- **服务商表单保存失败时静默**：合并后 `catch` 分支只剩一个状态标记，失败提示与错误日志都丢了，用户点保存后没有任何反馈。已恢复提示与日志。
- **模型设置页文案与测试不一致**：i18n 合并时保留了改版前的旧文案（「Add Provider」等），与已改版的界面和测试不符，现统一为改版后的「Add Model」等。
- **主题变量合并遗漏**：`globals.css` 的深色主题选择器在合并时需要手工并入，已确认 `dark` / `ink-blue` / `classic-dark` 三者一致。

## 说明

- **LSP 在正式版默认关闭，需显式开启**：语言服务器能力由 `CLAUDE_CODE_LSP` 环境变量控制（开发模式默认开，正式版需设为 `1`/`true`/`yes`/`on`）。这是 fork 编辑器/LSP 基础工作的既有设计，不是本次合并引入的；未开启时文件头的状态胶囊会显示「语言服务器不可用」，编辑与保存不受影响。

- **会话索引仍为显式同步**：上游改为在服务端启动时按优先级后台建索引，fork 保留自己的显式同步设计（`POST /api/sessions/sync-indexes` + 侧栏刷新按钮）。这是有意保留的差异，与本次合并无关。
- **工作区文件监听**：新架构用文件系统监听（`fs.watch`）刷新已打开的文件与目录，取代了旧实现里「Agent 编辑后主动推送刷新」的路径；两者覆盖范围相同。
- **本地测试环境限制**：上游 v0.6.3 新增的 `reviewService` / `workspaceWatch` 测试在 Windows 本机有 15 个红（符号链接需要管理员权限、系统级 `core.autocrlf=true`、`fs.watch` 时序），已确认在上游源码上原样复现，非本次合并引入，详见 `docs/known-pre-existing-test-failures.md`。

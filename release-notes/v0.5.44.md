# Claude Code Haha v0.5.44

> 本版本将后台 Agent 生命周期升级为 continuation-first runtime，同时补齐批量停止竞态、transient stream retry 与 Rule Federation 扩展。

## Highlights

- **确定性 Agent 状态机**：集中定义 queued、running、completed、failed、cancelled 状态与合法终态迁移；重复、晚到及 cancel/complete 竞态保持幂等。
- **主 Agent 持续执行约束**：只要任务列表仍有未阻塞、归属 `main-agent` 的 pending 工作，主 Agent 必须在同一回合启动最低编号任务并执行真实工具动作；状态汇报、重述计划或承诺稍后继续不再算作进展。只有全部剩余任务被依赖阻塞、需要用户输入或已完成时才能等待。
- **批量停止后台 Agent 的卡片与任务状态回写**：批量停止时，聊天卡片与后台任务会同步标记为 `stopped`；如果 stop 请求被拒绝，且任务仍处于 optimistic stopped，就回滚回 `running` 并清理对应通知，避免停止拒绝与终态消息乱序时留下悬挂的进行中状态。
- **Cancel epoch**：每次恢复执行递增 epoch；旧 epoch 的完成、失败或取消事件不能覆盖新执行。
- **Completion inbox**：后台 Agent 终态先进入最多 64 条的有界 inbox，在工具结果完成后的安全 continuation 边界按 sequence 顺序注入；每项最多消费一次，并保留 completed、failed、cancelled 语义。
- **Idle completion continuation**：修复 idle 状态下 completion 从 inbox 转入命令队列后被错误当作“未处理”而丢失 continuation 的竞态；刚完成的 Agent 现在会立即形成一次主会话通知，不再只留下 `queue-operation` 记录。
- **Stalled Agent reconciliation**：后台 Agent 连续 90 秒无活动时会向主 Agent 发出一次 stalled 通知；主 Agent 只做一次非阻塞状态收敛，runtime 已终态时消费结果，runtime 已不存在时释放或替换对应任务 owner，不进行连续轮询。
- **Task list convergence**：终态 Agent 通知到达后，主 Agent 必须在同一回合收敛其对应 TaskCreate 项；只有 Agent 明确完成全部分配范围时才标记 completed，部分结果或失效 runtime 会回到 pending 并记录剩余范围。
- **Bounded registry**：现有 AppState task registry 最多保留 64 个 Local Agent；只按 endTime、startTime、id 的稳定顺序淘汰最早终态且未被 UI retain 的任务，绝不淘汰运行任务。
- **会话恢复**：版本化 Agent runtime sidecar 持久化 registry、epoch、inbox 与消费进度；恢复时已失去进程的 queued/running Agent 明确转为 failed/interrupted，并生成一次失败 completion。
- **Watching / Agent Results**：扩展现有 Desktop Background Tasks drawer，分别展示运行中 Agent 与完成、失败、取消结果，并直接显示结果摘要；未创建第二套任务 UI 或 registry。
- **Transient stream retry**：默认 4 次，覆盖无 status 的 `api_error`、`overloaded_error`、`upstream_error` 以及短暂 socket 中断（包括 `socket closed` / `ECONNRESET` / `socket hang up`）等可恢复错误；HTTP status 已定义的错误（包括 4xx）、SSL 连接错误和 user abort 不重试。重试耗尽前只发出恢复提示，不提前显示最终错误消息。
- **Rule Federation 扩展**：新增 Kiro、Trae、Qoder、CodeBuddy、共享 AGENTS.md（OpenCode/Codex）、Devin 与 Zcode 的规则发现和归一化；Claude 原生规则继续最高优先级，同内容或同 canonical path 的外部规则会确定性标记为 duplicate / conflict / overridden-by-native，不会静默覆盖原生。无法安全映射的手动规则保持 fail closed，不会自动导入，只有用户明确选择 session / persistent 才会写入本地用户配置。
- **Desktop 版本**：Electron Desktop 权威版本更新为 `0.5.44`；根 CLI 版本保持 `999.0.0-local`。
- **本地索引存储上限可配置化**：`search-index-v1.sqlite`（全文/trigram 库）与 `index-v1.sqlite`（会话元数据库）原本共用硬编码 512 MB 上限、超限只停写不裁剪，导致历史堆积能长到 GB 级。现在两个库分别通过 `CC_HAHA_SEARCH_INDEX_LIMIT_MB` 与 `CC_HAHA_LOCAL_INDEX_LIMIT_MB` 环境变量独立调整（单位 MB）；未设置或值非法时回退到原 512 MB 默认值，默认行为零变化。
- **Plan 模式退出后权限模式保留**：Agent 自动进入 plan 模式并调用 `ExitPlanModeV2Tool` 退出时，`ExitPlanModePermissionRequest` 对话框会把默认焦点对齐到能保留用户 `prePlanMode` 的 keep-context 选项（`bypassPermissions`/`acceptEdits` → “Yes, and bypass/auto-accept edits”；`default` → “Yes, manually approve edits”；`auto` → “Yes, and use auto mode”）。用户直接按 Enter 就能拿回退出 plan 前的权限模式，不再出现从“跳过权限”悄悄降级到“询问权限”的行为。其他选项仍可通过方向键选择，语义未变。

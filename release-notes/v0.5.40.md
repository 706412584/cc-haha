# Claude Code Haha v0.5.40

> 本版本将 Agent Office 从视觉展示升级为真实可操作的多 Agent 工作台，并完善本地 Provider 协议转换、Hybrid Agent 编排、WeChat 会话恢复、Windows 首次安装体验与本地文件安全边界。

本说明面向 `v0.5.40` 最终用户与发布维护者。正式安装包从最终 reviewed merge SHA 构建，并通过 package smoke、冷启动与真实功能路径验收后发布。

## Highlights

- **Agent Office 真实工作台**：Office 直接展示 Main Agent、named Agent、TeamMember、SubAgent、background task 与 CLI Task 的真实运行状态，不再用 Renderer 伪造“工作中”或“已完成”。
- **可操作的任务调度**：显示 Task 的 `owner`、`blockedBy`、`blocks`、queue 与 stale queue；未阻塞任务支持立即处理、加入下一轮和多选调度，阻塞任务不会被错误派发。
- **Main Agent 状态更准确**：Main 会根据前台对话、工具调用、SubAgent、background command 和 ready/blocked Task 推导当前状态，不再长期错误显示为空闲。
- **Hybrid Agent 并行编排**：复杂任务使用 Task DAG、owner、wave、execution、file scope 与 verification 元数据；Main 启动 background Agents 后继续执行自己的关键路径，不以等待代理代替工作。
- **Provider 本地协议转换**：设置页明确区分 Anthropic Messages 原生协议、OpenAI Chat Completions 本地协议转换和 OpenAI Responses API 本地协议转换；转换仅在 cc-haha 本机完成，不额外经过第三方转换服务。
- **H5 关闭时 Provider 仍可用**：Desktop 管理的 Claude CLI 使用受限本地凭据访问 Provider proxy；关闭 H5 access 不再导致 OpenAI Chat / Responses 请求返回 `403 H5 access is disabled`。
- **WeChat 失效后可恢复**：遇到 `-14 session timeout` 时立即停止当前轮询、释放 typing controller，并在 Desktop 提示重新扫码；重新绑定不会清空白名单、已配对用户或默认工作目录。
- **Windows 首启体验修复**：普通终端继续使用内置 `node-pty` 与所选 shell，不依赖 Python；Git Bash 用于 Claude BashTool 和 Bash hooks；Python 仅是 Computer Use 桌面自动化的运行依赖。
- **Windows 路径与索引加固**：系统打开或定位文件前拒绝 UNC、mapped drive、DOS-device alias、reparse point、快捷方式和脚本格式；managed SQLite 目录与数据库文件使用仅当前用户可访问的权限。
- **Provider 保存不再持续加载**：保存成功后直接更新本地 Provider 状态；失败时展示明确错误，不再等待重复的全量刷新。
- **运行时日志去噪**：CLI `keep_alive` frame 静默处理，不产生 unknown message 日志，也不改变会话状态。
- **历史列表不再卡在优化完成状态**：Local Index 完成后，失效或不可达的旧 workspace 路径不再阻塞会话列表；路径探测超时会降级为缺失状态，历史会话仍可及时显示。

## Agent Office

### 真实状态与席位

- Main Agent、Team、SubAgent、Background Agent 与 CLI Task 共用现有 Activity、chat、team、task 和 message queue 数据源。
- Agent name 只与完全相同的 Task owner 关联，不根据标题或描述猜测负责人。
- Main Agent 状态按真实活动优先级派生：前台 chat/tool、运行中的 SubAgent、background command、ready Task、blocked Task，最后才是 idle。
- 相同活动来源保持稳定席位；活动结束后短暂保留为空闲员工，减少实时刷新导致的人物闪烁与换位。

### 任务调度与操作

- Task 卡展示负责人、前置依赖、后续阻塞关系和编排 metadata。
- 未阻塞 pending Task 可立即交给 Main；Main 正忙时进入现有消息队列，不提前伪造 `in_progress`。
- 支持多选 ready Task，并按稳定顺序提交调度请求。
- 队列消息支持立即发送、移除和 stale 标记。
- 可打开 SubAgent 记录、TeamMember 会话、background output，停止后台任务或向真实 TeamMember 发送消息。
- Renderer 不直接创建 Agent，不修改 CLI Task 权威状态。

### 视觉、主题与无障碍

- 保留原版像素办公室、PixiJS / Spine Chibi 角色、工位拜访、气泡、表情和低频趣味事件。
- white、light、eyeCare、dark 与 system 主题会同步应用到 React chrome 和 Pixi 场景。
- Office 文案支持英文、简体中文、繁体中文、日文和韩文。
- reduced-motion 开启后停止 Spine 时间轴、拜访和装饰动画，同时继续展示真实状态和任务更新。
- 默认以大尺寸 modal 打开，也可在设置中切换为独立 tab；同一 session 只保留一个 Office tab。
- Office 运行时保持 Desktop-only lazy load，不增加移动 H5 的首屏 bundle 和默认交互负担。

## Hybrid Agent 编排

- Main Agent 默认拥有需求理解、关键路径实现和聚焦验证。
- 仅当至少存在两条未阻塞、文件范围不重叠、且不依赖彼此结果的执行线时并行 kickoff。
- 复杂计划通过 Task metadata 记录：
  - `owner`
  - `wave`
  - `execution`
  - `fileScope`
  - `verification`
- 启动 named background Agents 的同一个 assistant turn 中，Main 必须继续执行自己的真实工具动作。
- 小任务、同文件修改和链式依赖任务不进行无意义 fan-out。
- Coordinator mode 仍保持纯协调，不在该模式中偷偷承担实现任务。

## Provider 与本地协议转换

### 协议标识

设置页使用以下明确名称：

- `Anthropic Messages（原生协议）`
- `OpenAI Chat Completions（本地协议转换）`
- `OpenAI Responses API（本地协议转换）`

OpenAI 两种格式由 cc-haha 本地 Provider proxy 转换为 Claude CLI 使用的 Anthropic Messages 语义。请求不会为了协议转换而发送到额外的第三方转换服务；配置的 Provider upstream 仍是唯一模型服务端点。

### Desktop 本地鉴权

- Electron 启动 server sidecar 时生成 scoped local access token。
- Desktop renderer 和受控 Claude CLI 通过该 token 访问准确的 loopback origin 与 Provider proxy path。
- H5 access 关闭时，本机受控调用仍可使用 OpenAI Chat 与 Responses Provider。
- 缺少或错误的 internal token 会被拒绝。
- internal token 不写入 Provider 配置、不转发给 upstream，也不应出现在诊断日志中。
- Anthropic Messages 原生 Provider 继续直接使用原协议，不经过 OpenAI 转换路径。

### Provider 编辑体验

- 保存成功后直接合并服务端返回的 Provider，不再串行等待重复的 Provider 与 Settings 全量刷新。
- 保存失败会恢复按钮状态并显示具体错误。
- Provider 标签和格式选择器同步显示原生协议或本地转换类型。

## WeChat 会话恢复

当 WeChat adapter 收到 `-14 session timeout`：

- 停止当前 long-poll 循环，避免持续重试失效 session。
- 销毁 typing controller，避免残留输入状态。
- 当前失效周期只发布一次临时 runtime status。
- Desktop 显示“需要重新扫码绑定”，而不是继续显示运行中。
- 重新绑定仅替换登录凭据，保留 `allowedUsers`、`pairedUsers`、`defaultWorkDir` 等无关配置。

## Windows 运行时与首次安装

- Electron 普通终端通过 `node-pty` 启动用户选择的 PowerShell、Git Bash 或其他 shell，不要求 Python。
- Claude BashTool 与配置为 Bash 的 hooks 使用 Git Bash。
- Computer Use 才需要可用的 Python 运行时；错误提示会区分“未安装”和“应用 PATH 不可见”。
- 即使 packaged 应用继承到精简 PATH，也会从可信 Windows 系统目录发现 Windows PowerShell。
- PowerShell 与 Git discovery 使用可信绝对路径和规范化安装根，避免从当前目录加载同名恶意二进制。
- 支持 Git for Windows 的 `cmd`、`mingw64`、`mingw32`、`usr/bin` 与 `bin` 安装布局。

## 本地文件与数据安全

- Electron `openPath()` 与 `showItemInFolder()` 只接受已存在的本地绝对路径。
- Windows 在访问文件系统前拒绝 UNC、device namespace、mapped network drive、SUBST / DOS-device alias 与任意 reparse point。
- 打开文件时额外拒绝可执行程序、脚本、快捷方式和 Internet Shortcut；会话输出文件只允许在文件管理器中定位。
- Windows 路径检查通过可信 Windows PowerShell 和固定 P/Invoke 脚本异步执行，不阻塞 Electron 主线程。
- managed SQLite 目录使用 `0700`，数据库、WAL、SHM 与 journal 文件使用 `0600`。
- managed database 拒绝 symlink、hardlink、非普通文件与目录逃逸。

## 其他修复

- 静默处理 Claude CLI `keep_alive` frame，不再记录 unknown message，也不改变会话 activity。
- Local Index 会话列表改用有界、并行的 workspace 可用性探测；断开的网络盘、mapped drive 或已移除 worktree 不再让“优化历史记录”完成后的列表请求等待到 120 秒超时。
- Prewarmed session 的 inspection 验证等待 SDK init readiness，而不是仅等待子进程进入 session map，减少高负载 CI 和真实启动竞态。
- Package smoke 与 coverage runner 从脚本所在仓库解析 candidate root，不再受调用时 cwd 影响。
- Windows / Linux 测试 fixture 使用对应平台的真实路径语义，减少跨平台误报。
- 吸收上游 Claude Code Haha `v0.4.9` 的 Provider proxy auth、动态系统代理、bundled ripgrep 与 SQLite local indexing 更新。

# Claude Code Haha v0.5.37

> 本版本合并上游 `v0.4.7` 与 fork 长会话修复，重点覆盖模型兼容、长任务恢复、权限与后台任务、技能市场、会话活动、media-gen 多媒体生成，以及移动 H5 / Android 本地运行探索。

本说明面向最终用户与发布维护者。桌面端版本号已更新为 `0.5.37`；对应安装包由 `v0.5.37` tag 触发的发布流程构建并上传。

## Highlights

- **上游 `v0.4.7` 能力合入**：加入 GPT-5.6、GPT-5.6 Pro 与 GPT-5.6 Codex 支持，新增 `Ctrl+F` / `Cmd+F` 页面内查找，并改善长任务流式传输、WebSocket watchdog、后台任务、并发权限请求和 Claude Resume 会话发现。
- **长会话恢复更可靠**：重连或 compact 后重放的 assistant 尾部文本只在完全一致时去重，不再因为文本片段被旧尾部包含而误吞新增内容。
- **对话接续首轮可靠启动**：点击“从这里继续”创建新会话时，服务端会先完成接续摘要 staging，再启动自动发送的首个用户回合，避免首条“继续”消息因异步竞态未被处理。
- **compact 后上下文用量可恢复**：summary-only compaction 完成后会触发有界重试，并在空闲恢复阶段再刷新一次 context usage，避免用量指示长期停留在压缩前的高占用状态。
- **技能市场流程补齐**：支持来源聚合、搜索和筛选、详情与文件查看、安装确认、卸载和状态同步；安装边界会检查名称冲突、非法名称、空文件列表、文件数量与单文件大小，并展示来源安全状态。
- **会话活动与 SubAgent 更清晰**：活动面板统一整理任务、团队、后台任务与 SubAgent 状态；SubAgent 可进入独立运行页面查看，配套 mascot 提升不同 agent 状态的辨识度；有实时活动或最近更新时间时不再重复显示“进行中”。
- **media-gen 覆盖图片与视频工作流**：原 image-gen 扩展并更名为 media-gen，支持最多 16 个可排序、启停的动态 Provider；每个 Provider 可分别选择图片生成、图片编辑、视频生成、视频编辑和视频扩展模型，并可从远端 `/models` 拉取候选模型；同时支持文生图、图像编辑、文生视频、图生视频、Grok 视频编辑与视频扩展。
- **移动端探索保持隔离**：移动 H5 与 Android Termux 本地 runtime 继续作为开发者 spike 验证，移动布局和运行时探测保持在移动端路径内，不改变桌面端默认体验；这不代表 Android 已成为正式支持的发布平台。

## 长会话与恢复

- 修复 hydrated assistant 回复在 reconnect / compact 后收到 replayed suffix 时的误去重：只有规范化后的完整文本完全相同才视为重复，真实追加的尾部文本会继续显示。
- 修复对话接续自动首轮的服务端竞态：`set_handoff_summary` 与紧随其后的 `user_message` 现在按 session 串行衔接，首个 turn 会等待缓存摘要读取和 system prompt staging 完成后再启动 CLI。
- compact boundary 到达后会提升 context usage 刷新代次，避免 summary-only compaction 没有常规 assistant 消息时漏掉刷新。
- 上下文用量刷新采用有限次数的延迟重试，并保留一次空闲恢复刷新，使压缩后的 context meter 能重新读取服务端状态，而不是永久显示旧的 `100%`。
- 针对 assistant 完整重放、尾部追加、compact 后刷新和空闲恢复补充了桌面回归测试。

## 上游 v0.4.7 合入

- OpenAI 官方登录支持 GPT-5.6、GPT-5.6 Pro 和 GPT-5.6 Codex 的模型目录、选择、迁移与会话恢复。
- 长时间运行的 turn 在流式中断、watchdog、重试或 WebSocket 重连后能更准确地恢复或完成，减少界面卡在 running 以及最终 assistant 输出缺失的情况。
- 同一会话中的并发 permission / AskUserQuestion 请求分别保留与响应；活跃 turn 期间禁止切换权限模式。
- 后台任务的停止、完成和活动状态同步更完整；定时轮询避免重叠与过期响应覆盖，定时任务完成输出不再重复写入。
- Claude Resume 可发现桌面创建的会话，并加强 session 文件结束写入的 flush。
- Kimi K2.7 自动使用其必需的 thinking 配置，避免未显式开启 thinking 时请求失败。
- 新增 `Ctrl+F` / `Cmd+F` 页面内查找，并修复从 Explorer 打开目录时已有窗口可能被隐藏的问题。

以上条目来自合入的 upstream `v0.4.7`。其中原上游 issue 编号（如 #974、#983、#986、#988、#989、#990、#993、#997）属于上游项目，不应解释为当前 fork 的同号 issue。

## 技能市场与会话活动

- 技能市场可按来源、安全状态和安装状态筛选，并支持分页、详情、文件树与单文件内容查看。
- 安装和卸载均需确认；操作完成后会同步市场列表、详情和设置页技能列表，失败时展示分类错误。
- 市场内容属于外部来源：界面展示来源状态与安全报告，但安全标签不替代用户审查。服务端拒绝路径穿越 slug，并阻止非法名称、名称冲突、空文件列表、过多文件或单文件过大的技能进入安装流程。
- 会话活动面板汇总任务、团队、后台任务、SubAgent 和来源信息，并对重复任务行做归并，减少长会话中的重复展示。
- SubAgent 运行记录可在独立页面打开；状态 mascot 用于辅助区分 agent 活动状态，不改变任务执行语义。

## media-gen 图片与视频生成

- **插件改名与定位扩展**：原 `image-gen` 更名为 `media-gen`，从单一图片生成插件扩展为图片与视频的统一编排插件；marketplace、插件 manifest、MCP server、Agent、skill、服务端 catalog 和相关测试均同步使用新 ID 与 `MEDIA_GEN_P*` 配置前缀。
- **动态 Provider 与显式路由**：支持最多 16 个 Provider，可新增、删除、启停、折叠和调整优先级。Provider 数组顺序决定图片 fallback 和旧 `provider_index` 的路由顺序；新增稳定的 `provider_id`，排序后仍能命中原 Provider。两种参数同时提供时必须指向同一 Provider，避免请求被错误路由。图片生成支持按已启用 Provider 顺序自动回退，视频工具继续要求显式选择 Provider。
- **图片生成与编辑增强**：`generate_image` 支持 Grok `grok-imagine-image` 与 `grok-imagine-image-quality`，`edit_image` 支持 `grok-imagine-edit`；Grok 图片请求支持 `aspect_ratio` 与 `1k` / `2k` resolution。原有 OpenAI-compatible、GPT Image、Gemini、Flux、Stable Diffusion、DALL-E 与 Agnes 图片模型继续通过能力映射和兼容请求路径使用。
- **本地图片输出**：图片生成和编辑继续支持 `output_dir`。provider 返回 base64 时会解码保存，返回 URL 时会经过 URL 安全校验后下载；保存成功后返回本地文件链接，避免大段 base64 长期占用会话上下文。
- **视频生成与图生视频**：新增 `generate_video`，同时支持 Grok 与 Agnes 协议。Grok 使用 `/videos/generations` 并通过 `/videos/{request_id}` 轮询，图生视频使用顶层 `image_url`；Agnes 使用 `/videos` 与 `/agnesapi?video_id=...`，图生视频使用 `image`。Grok 视频生成支持 1–15 秒、横竖比例和 resolution 参数。
- **Grok 视频编辑与扩展**：新增 `edit_video`，通过 `/videos/edits` 根据 prompt 修改已有视频；新增 `extend_video`，通过 `/videos/extensions` 延展已有视频，单次扩展时长为 1–10 秒。两者复用 Grok 异步任务轮询，并要求显式 Provider。
- **五类默认模型与模型发现**：每个 Provider 可分别设置图片生成、图片编辑、视频生成、视频编辑和视频扩展模型；工具调用显式传入的模型仍优先于默认值。新增 `list_providers` 与 `list_models`，桌面端也可通过 Provider 的 `/models` 接口拉取候选模型，五个模型字段共享候选列表且仍允许输入自定义模型 ID，不会根据模型名称擅自猜测用途。
- **动态专用设置面板**：桌面插件设置页为 media-gen 提供动态 Provider 编辑器，支持新增、删除、折叠、启停和上下排序；达到 16 个时停止新增。已有 Provider 打开配置时默认折叠，仅先展示列表；新增 Provider 保持展开。Provider 在 Base URL、有效凭据和任意一个模型齐备后即显示就绪，不再要求五类模型全部填写。
- **服务商快速选择与完整候选列表**：可从桌面“服务商”设置中快速选择并预填名称与 Base URL，下拉显示全部已保存服务商，不再只显示 OpenAI Chat / Responses 格式。兼容且已有凭据的服务商会建立安全引用；其他服务商仍可选择和预填，但不会错误复用 Key，可在 media-gen 中单独填写。下拉列表有独立高度与滚动区域，不会带动外层配置弹窗。
- **模型选择体验**：远端 `/models` 响应保持完整候选，不按模型名称或媒体用途预过滤；五类模型字段使用可编辑 combobox，支持输入筛选、自定义模型 ID、键盘选择与 Portal 渲染，避免被 Provider 卡片裁剪。
- **配置迁移、保存保护与中文化**：旧 `image-gen` 及 media-gen P1/P2/P3 配置会一次性迁移到动态格式，旧单一 `MODEL` 仅映射为图片生成模型，不猜测其他用途。API Key 使用安全存储并按“保留 / 替换 / 清除 / 引用”更新，不进入普通 settings、renderer 响应或日志；跨 origin 修改 Provider 时禁止继续保留旧 Key，失效引用只隔离对应 Provider，不阻断其他 Provider 启动。宿主加载器会忽略已安装旧版插件遗留的 P1/P2/P3 MCP 环境占位符，确保动态配置升级后 media-gen 仍能注册 MCP server 和对话工具，无需卸载重装插件。迁移或安装失败会恢复 settings、安装 registry 与凭据状态。插件“配置”按钮、配置标题、状态、toast 和说明文案提供多语言显示，服务商编辑页不再展示订阅推广卡片。
- **私网 Provider 与媒体 URL 安全边界**：动态 Provider 默认允许使用 localhost 和局域网 Base URL，便于连接本地模型服务与内网网关；用户明确配置的 Provider API 请求可以访问这些地址，但 Provider 返回的图片、视频等媒体 URL 仍经过严格 SSRF 校验，拒绝 loopback、局域网、link-local、云元数据地址和 DNS rebinding。Provider 请求与媒体下载都限制 HTTP(S)、重定向次数、HTTPS 降级和响应大小，携带 Authorization/Cookie 时不会向不同 origin 转发凭据。
- **有界响应读取**：URL 图片与参考图片限制为 25 MB，provider JSON 限制为 35 MB，base64 解码前也会检查预估尺寸；同时校验远程参考资源的 `image/*` Content-Type，避免恶意或异常响应无限占用内存。
- **真实网络运行时修复**：修复 Undici 固定 DNS 地址时 `lookup({ all: true })` 的回调格式，通过已验证地址数组保持 DNS pinning；超限响应改用活动 stream reader 取消并释放锁，避免真实 Provider 请求出现 `ERR_INVALID_IP_ADDRESS` 或 locked stream 错误。

## 工程质量与发布可靠性

- PR 质量流水线统一使用 Bun `1.3.14`，并在需要文件搜索的 Linux job 中显式安装 ripgrep，减少运行环境差异。
- 测试按文件和检查域隔离运行，降低共享 sandbox、环境变量或临时状态对其他套件的影响。
- coverage 检查使用独立进程收集分片结果，再合并 LCOV 证据，避免覆盖率 reporter 或进程退出时序影响门禁结果。
- provider/chat contracts、adapters、persistence、server、desktop、native 与 docs 分域验证；变更策略通过 label 与维护者 approval 约束敏感范围。
- 这些调整用于提高 CI 与发布证据的可重复性，不改变面向用户的运行时配置。

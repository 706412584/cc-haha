# Code Council v0.9.3

补丁版本：修复 v0.9.2 上 H5 设置页「外层链接」（Cloudflare 公共访问/隧道）点击「开启连接」后显示「操作失败，请重试」的回归。包含 v0.9.2 全部内容（中转会话 ID 轮换、大会话历史完整浏览），并新增公共访问设备存储损坏恢复。

## 修复

- **公共访问设备存储损坏导致整个隧道入口 400**（`3d42d5be1`、`958dee1b7`）：`public-access-devices.json` 在打包/安装瞬间若进程被 kill，可能落成零字节或截断的 JSON。`PublicAccessServer.load()` 此前只对 `ENOENT` 容错，`SyntaxError` 会冒泡到 control 的 catch-all，把整个 H5 设置页「外层链接」区域打成 400 genericError，看起来像是隧道功能整体不可用。
  - `load()` 把 `SyntaxError` 单独分支处理：损坏文件 rename 为 `<storePath>.corrupt-<时间戳>-<随机>` 保留现场，按空 store 重建并落盘。已配对手机需重新扫码，但不再卡死整个隧道入口。
  - 备份名追加随机后缀，同一时钟连续两次恢复不会撞名覆盖前一份备份。
  - 备份 rename 失败时设置 `preserveCorruptOnDisk` 标志，本实例 lifetime 内 `persist()` 全部 no-op，原文件字节保持不变；console.warn 把恢复失败显式暴露出来，避免后续 revoke/approve 悄悄覆盖原始损坏字节。
  - 其他错误（EPERM/EACCES 等）仍然 throw，语义不变；`version > 1` 的合法 JSON 仍按 fail-closed 抛错，不会被容错吞掉。

## fork 既有定制（继承自 v0.9.2）

- **中转会话 ID 轮换**（`fdec0f3da`）：按会话计数的中转（如 OpenCode Zen Go，100 次上限）打满后返回 `400 session_request_limit_exceeded`，同一会话连 `/compact` 都被拒，只能导出重开。proxy 检测到该错误后自动把发给上游的会话 ID 轮换为 `原ID-r<n>` 并重试一次，对话原地续跑、CLI 无感。触发有三重门槛（仅 upstreamHeaders 模板含 `$SESSION_ID` 的 preset、恰为 400、body 含精确错误码），无关 400 不受影响；轮换 ID 成功过则计满后继续轮换，从未成功就被拒则永久禁用该会话的轮换；本地 trace 与 prompt cache 路由始终用原 ID；状态带 6 小时 TTL、每会话 25 次轮换上限。
- **大会话历史完整浏览**（`0b0c58091`、`2276d91ab`）：普通打开默认加载最近约 500 条（真实 43 MB 会话实测 314 ms 首屏）；滚动到顶部自动补页；新增「加载全部 / 取消」；头部计数改为「已加载 N 条」。修复两类空白：最近几页全是空输出/后台唤醒记录时自动跨过不可见尾页继续补到可见对话；分页响应中剥除 thinking 的 `signature` 鉴权包裹字节。移动端 /m/ 同步获得滚动自动补页与加载全部；修复 H5 上 Spinner/HaloDot 循环动画停转；500 条补页的 tool 配对从每页全量重扫改为 Map 索引。原始 JSONL 全程只读，不迁移、不截断、不去重。

## 升级建议

- 直接覆盖安装即可。
- 首次访问「外层链接」区时若检测到损坏的 `public-access-devices.json`，会自动备份成 `.corrupt-<ts>-<rand>` 并重建空 store，已配对手机需重新扫码。
- 若备份 rename 失败（极少见，通常是文件被外部占用），原文件字节会被保留，控制台会输出 `[public-access] devices store is unparseable and could not be backed up`，请手动处理 `CLAUDE_CONFIG_DIR/cc-haha/public-access-devices.json` 后重启桌面端。

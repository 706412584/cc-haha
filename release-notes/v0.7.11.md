# Claude Code Haha v0.7.11

修复**自动回答问题**两个真实缺陷：**开了不生效**与**问题永久卡住**。无上游合并。

## 自动回答：推荐项直接解答，失败不再卡死

**背景**：开启「自动回答问题」后，等待超时系统会把问题交给一个小模型来选答案。排查发现两个缺陷叠加，让这个功能在部分配置下完全失效：

1. **带「(Recommended)」标记的选项本可以秒答，却要过模型。** 早期实现会先解析选项标签里的推荐标记、直接选它（零模型调用）；后来一次改写把这条确定性路径删掉了，只剩模型一条路。而提示词里仍然要求模型给推荐项加这个标记——生产端还在写，消费端已经没了。
2. **模型失败后，问题永远悬着。** 小模型若是推理模型（会把输出预算全花在内部思考上、正文为空），每次决策都失败；失败后系统只是记一条日志就返回，而运行时**没有任何机制会过期一条待答的问题**——CLI 就一直等一个永远不会来的答案，会话被无限占用。

**现在**：

- 带 `(Recommended)` 标记的题**直接本地解答**，不调模型、零成本、不会失败；只有没有推荐标记的题才交给模型。
- 模型也给不出答案时，**明确拒绝该问题**：请求被应答、CLI 解除阻塞，模型收到「停下来等用户」——不再永久卡住。
- 拒绝日志带上模型返回的**停止原因与正文长度**，下次排查不用猜（本次排查就靠它定死了「推理模型烧光预算」这个根因）。
- 你在等待期间操作了问题卡片（取消自动回答或手动作答），系统**不会**用拒绝覆盖你的操作。

## 验证

- 新增/改写测试：推荐项本地解答且不调模型、推荐后缀契约（含二义性与近似标记不误判）、模型失败时拒绝并解除阻塞、用户取消时不拒绝。
- 实测定位根因：用当前配置对真实中转各跑 10 次——推理模型 0/10 成功（512 token 全烧在推理上、正文为空），非推理模型 10/10 成功且快 8 倍。
- CI 全绿（server / coverage / policy / contracts 等）。

## 说明

- 修复后，**没有推荐标记的题仍然要过小模型**。若你当前线路的小模型（haiku 槽位）是推理模型，建议换成非推理模型（实测成功率 10/10 且快 8 倍）。
- 曾考虑「模型失败时回退解析推理内容」，实测否决：推理内容里没有答案，只有模型对提示词本身的纠结。

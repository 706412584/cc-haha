# Claude Code Haha v0.8.6

v0.8.5 之后修复一处实机 resume 失败：**worktree 会话恢复时找不到 transcript**。

## 实机问题

在项目里用 worktree 工作（EnterWorktree 切到 `.claude/worktrees/<name>`）后继续对话，桌面端报 `cli_runtime_exit`：

```
CLI process exited unexpectedly (code 1): ... errors:["No conversation found with session ID: <id>"]
```

之后该会话的每条消息都以同样错误失败。

**根因**：会话在主项目目录创建，transcript 也留在主项目的 projects 目录；中途切入 worktree 只是往 transcript 追加一条 `session-meta.workDir` 记录。桌面端服务端把这条记录读回来作为 CLI 的 cwd（worktree 目录），CLI 收到 `--resume <会话ID>` 后按 **cwd 推导** transcript 路径——worktree 的 projects 目录里没有这个文件，于是报"找不到会话"退出。

**修复**（`src/utils/sessionStorage.ts`）：

- 按 cwd 推导的路径找不到 transcript 时，回退到仓库的**兄弟 worktree 项目目录**查找（先精确项目目录，再同一仓库的 worktree 根；不扫描无关项目，避免跨仓库误取）。零字节的截断副本同样跳过，继续找有效副本。
- `getLastSessionLog` 的 `fullPath` 从「cwd 推导的猜测」改为**实际读到的路径**。这一处同样关键：resume 会把活动项目目录切换到 `dirname(fullPath)`，用错误路径会让恢复后的新消息写进 worktree 的项目目录。

## 验证

- 新增回归测试（真实 git 仓库 + worktree）：transcript 写在仓库根、cwd 切到 worktree 后必须能找到并报告根路径；零字节诱饵不得遮蔽有效副本。**两个用例在修复前均失败**（stash 验证）。
- session 相关套件 36 过（retention / flush / exit / branching / title / 新增 worktree-resume）。
- `conversations.test.ts` 149 过（2 个 RE Pipeline 失败为预存，见 `docs/known-pre-existing-test-failures.md`）。
- 独立子代理审查（APPROVE）：核实 `fullPath` 全部消费点只用 `dirname` 或透传，改为真实路径语义严格更正确；确认 ENOENT 回退是冷路径，无性能退化；审查提出的「零字节遮蔽」一项已一并修复并补测试。

## 说明

- 服务端仍传裸 sessionId（上游协议），本修复选择 CLI 侧回退；更彻底的方案是服务端直接传 `--resume <transcript.jsonl>` 绝对路径（CLI 已支持该分支，不依赖 cwd），留待后续。
- 若还发现「以前有、现在没有」的功能，欢迎继续报告——核对清单仍在维护。

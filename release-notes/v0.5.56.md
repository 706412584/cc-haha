# Code Council v0.5.56

> 本版本合并上游 v0.5.3，并修复后台子代理“空报完成”与 Esc 暂停被任务通知强行唤醒的问题；同时保留本地 Provider / 桌面定制能力。

## 重点更新

### 上游 v0.5.3 合并

- 吸收上游桌面端图片生成（Provider 支撑、缩略图预览、生成/编辑工具分离）。
- 输入框内联 @提及 pill、Workbench 可在系统浏览器打开。
- 新增 FennoAI、七牛云 AI 等 Provider 预设与模型选择改进。
- 一批桌面稳定性修复：设置标签排序与侧栏对齐、完成回合变更刷新、rewind 部分快照恢复、回合结束后过期任务清理、思维块拆分/折叠、终端 PTY 回收等。
- 合并过程中清掉 PR #146 残留的 server/desktop CI 失败项，保证合入路径可过门禁。

### 后台子代理完成通知可信度

- 完成通知不再只写 `Agent "X" completed`。
- 从子代理 transcript 统计 `Edit` / `Write` / `NotebookEdit` 的成功与失败次数，写入：
  - summary：`completed (no file edits)` 或 `completed (file_edits=N)`，并附带 `tool_uses`
  - 可选 XML：`<outcome><file_edits>…</file_edits><file_edit_errors>…</file_edit_errors></outcome>`
- `status=completed` 仍只表示生命周期结束，**不代表一定有工作区落盘**。
- 编排提示明确：若任务本应改文件但 outcome 显示 `no file edits` / `file_edits=0`，应把 Task 退回 pending 并重派或核对，而不是直接标完成。

### Esc 暂停不再被任务通知强行唤醒

- 用户按 Esc 暂停后，后台 Agent 的 `task-notification` **不会**立刻开新一轮主对话。
- 通知保留在队列中，随用户下一次真实输入一并送达模型。
- 用户自己排队的 prompt 在暂停期间仍可正常处理。

### Provider 与停止链路

- 保留 K3 / 兼容模型的 `xhigh` 推理档位，避免合入上游时被错误回落。
- 冷重连后的 stop 失败路径更稳定，避免“已停但仍像在跑”的悬挂状态。

### Provider 预设本地策略

- 隐藏赞助 featured 位：`TeamoRouter` / `玄枢API` / `FennoAI` / `七牛云 AI` 改为 `deprecated` 墓碑（去掉 promo / 推广链接），添加列表不再展示；已配置用户仍可解析运行时。
- 恢复 `接口AI` 为可选预设，且不带广告文案与推广链接。
- 胜算云保持退役。

### 桌面端清理

- 去掉 ContextUsage 中只写不读的 chat-state ref 与无用 idle recovery 残留。
- 图片批注入口与新建会话权限复位相关修复随合入路径保留。
- 移除模型选择弹窗内的搜索过滤小功能（上游 v0.5.3 合入，本地不需要）；`SearchField` 组件本身保留供其他页面使用。

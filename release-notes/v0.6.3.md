# Claude Code Haha v0.6.3

本次更新以**合并上游 Claude Code v0.6.2** 为主，并修复了合并后实测发现的两个真实缺陷。

## 合并上游 v0.6.2

- **Provider 请求兼容设置**（上游 #1290）：服务商编辑中新增「回复输出预算」与「高级兼容设置」，可设置最大输出 token、已知端点输出上限、输出 token 参数字段，以及采样参数、推理参数、并行工具调用、结构化输出四项能力开关。仅对 OpenAI 兼容格式显示，不影响 Anthropic 格式。
- **计划模式审批携带权限模式**（上游 #1254）：计划审批弹窗新增「批准并自动接受编辑」与「批准并跳过权限」，与官方终端行为一致；修复批准后实施阶段对每个工具都询问权限的问题。
- **Computer Use**：点击动画资源改从运行中的原生 helper 目录解析，不再依赖 SwiftPM 生成的资源访问器（后者在正式安装包里会回退到构建机路径导致资源加载失败）；JavaScript 单元内支持 `setTimeout`/`setInterval` 等定时器，归属当前单元并在结束时清理。
- **流式总时长上限**随「请求超时」同步放宽（上游 #1307），不再出现「调大超时后仍撞 600 秒上限」。
- **代理协议收尾与输出预算契约**：新增协议跟踪观测链，强化 Responses 流的终态与工具参数校验。
- 会话改动卡片支持展开状态跨虚拟滚动保持；文件改动按回合归属。

## 修复

- **修复消息重复渲染**：流式进行中若历史回包到达，同一回合会在界面上渲染两遍（回复气泡与用户气泡各重复一次）。实时写入的消息不带 transcript 身份，冷合并按身份合并时只能将其**追加**而非覆盖，且后续没有任何路径会移除该副本。现已让中途回填同样执行身份回填，并修复由此暴露的反向问题（回填后流式续接被劈成两条）。
- **修复权限模式更新抛错**：上游用模块级 `require()` 绕开循环依赖，在 Bun 下（尤其带 `--feature` 标志时）它会返回**空且被永久缓存**的模块快照，导致 `transitionPermissionMode` 恒为 undefined——每次 `setMode` 权限更新（如计划审批弹窗）都会抛错。改用静态导入解决。
- **恢复合并过程中被覆盖的 fork 行为**：OpenAI 兼容代理的超长工具名映射（>64 字符）、thinking 透传、Provider 定制与 main 模型能力解析。
- 补齐 package-smoke 的资源检查与 plugin-seed 校验。

## 已知问题

- **macOS 原生 GUI 集成测试 `testVisibleCursorSurvivesRepeatedClicksAndTracksExposedBackgroundWindow` 在 CI 上失败**。该测试由上游 v0.6.2 新增、上游从未在 CI 执行过；它让测试进程与目标进程争夺前台焦点，触发产品的焦点代际防护。**不影响桌面端任何功能**，已登记于 `docs/known-pre-existing-test-failures.md`，将在后续单独处理。

## 安装

本次为草稿构建。Windows 与 macOS 产物可能未签名；macOS 未签名包会附带 `install-macos-unsigned.sh`。

- macOS：`Claude-Code-Haha-0.6.3-mac-arm64.dmg` / `Claude-Code-Haha-0.6.3-mac-x64.dmg`
- Windows：`Claude-Code-Haha-0.6.3-win-x64.exe` / `Claude-Code-Haha-0.6.3-win-arm64.exe`
- Linux x64：`Claude-Code-Haha-0.6.3-linux-x86_64.AppImage`、`Claude-Code-Haha-0.6.3-linux-amd64.deb` 或 `Claude-Code-Haha-0.6.3-linux-x86_64.rpm`
- Linux ARM64：`Claude-Code-Haha-0.6.3-linux-arm64.AppImage`、`Claude-Code-Haha-0.6.3-linux-arm64.deb` 或 `Claude-Code-Haha-0.6.3-linux-aarch64.rpm`

# Claude Code Haha v0.7.8

新增**团队续跑**：团队中断后，卡片上会出现「继续未完成的任务」，只跑没做完的，做完的自动跳过，执行到一半的由你逐个确认。无上游合并。

## 团队续跑

**背景**：团队因手动停止、API 报错、应用重启或运行时丢失而中断后，之前唯一的出路是解散重建——已完成的工作、成员分工、任务分配全部作废。

**现在**：中断的团队卡片上出现「继续未完成的任务」：

- **已完成的任务自动跳过**，不会重跑。
- **执行到一半的任务默认不跑**——它们可能已经写过文件或执行过命令，静默重跑会重复副作用。这类任务会列在确认弹窗里，你勾选哪些才重跑哪些。
- **没开始的任务正常跑**，成员、模型、任务归属沿用原计划。

**判定依据**：任务清单本身分不清「从未开始」和「跑到一半死了」——一旦把执行中的任务重置为待办就永远分不清了。所以中断时会把每个任务的真实状态冻结到计划记录上，续跑只看这份快照。

## 顺带修好的三个缺陷（拿真实中断计划验证时发现）

- **旧的中断计划会重跑已完成的活**。快照机制之前中断的计划没有这份记录，续跑会把全部任务当成「从未开始」。现在从任务清单回填快照；回填失败时**拒绝续跑**并说明原因，而不是猜。
- **崩溃留下的陈旧成员挡住重启**。崩溃把成员留成「活跃」但会话已死，启动时报「成员已存在」。现在以成员会话为准：会话已死的名字可替换，会话还活着的仍拒绝。
- **续跑不拉起领队会话**。与批准同一种死路——现在两者都会在动作前确保领队已连接；过期或伪造的请求不会误启动进程。

## 验证

- 拿磁盘上真实的 8 任务中断计划模拟：**5 个已完成跳过、1 个执行中进入确认清单、2 个待跑**。
- 服务端相关套件 146 pass / 0 fail；桌面端 21 pass；`tsc --noEmit` 0 错误；CI 全绿（含覆盖率门禁）。
- 独立子代理审核通过，其提出的边界收紧（启动门控加计划 ID）与失败可观测性均已处理。

## 说明

- 续跑的语义是「继续未完成」，不是「重来一遍」。若你想全部重跑，解散团队重新发起即可。
- 该功能是上一版（v0.7.7）「批准前拉起领队」修复的直接受益者：重启后续跑的主场景正是领队未连接。

# Claude Code Haha v0.7.0

新增**编排模式提示词自定义**：输入框 `+` 菜单里的编排模式、Solo 模式、逆向编排三个开关，背后的系统提示词现在可以在设置里直接编辑。同时修掉两处「信号说错话」的问题——大会话底部那条红色英文横幅，以及供应商测试里被误标的「本地协议转换」。

## 编排模式提示词可自定义

设置里新增**编排提示词**页，三个模式各一份可编辑文本。

- 以内置提示词为起点编辑，改完保存；「恢复默认」一键回到内置版本。左侧列表和编辑区都显示**已自定义 / 默认**徽标，一眼看出哪个模式被改过。
- 支持 Markdown 预览切换，编辑器显示字符数上限。
- 未自定义的模式继续使用内置提示词，行为与之前完全一致。
- 保存后**不立即打断当前会话**，下次切换模式或新建会话时生效——正在跑的任务不会被中途换掉提示词。

自定义内容**完全替换**默认提示词，不是追加。这对逆向编排模式尤其需要留意：默认提示词里的授权门禁与拒绝 jailbreak 条款也在被替换的范围内，编辑该模式时界面会给出提示。

## 提示词改由文件传递（顺带修掉一个静默覆盖）

三个模式的提示词原本走命令行参数传给 CLI。这有两个问题，本次一并解决：

- **Windows 命令行长度上限 32767 字符**，而三份提示词本身已占 4–13KB。用户写长提示词会直接导致 CLI 启动失败，且只在事后报错。现在改为写入文件、传文件路径，不再受长度限制。
- **「从之前的会话继续」会静默吃掉模式提示词**。两者原本都用同一个命令行参数，而该参数是标量——后一个覆盖前一个。也就是说开着 Solo 或编排模式点「继续」，模式提示词实际并未生效。现在两者合并进同一个文件，模式提示词在前、交接摘要随后。

每会话的提示词文件在会话真正结束时删除，服务启动时也会清理上次被强杀留下的残留。

## 两处「信号说错话」

- **大会话不再弹英文红条**。会话记录超过服务端上限时，服务端会拒绝构建「每回合改动文件」预览卡片——这是一道有意的性能闸门，不是故障。此前聊天区会把它当错误，在对话末尾渲染一条原始英文提示。现在这类限流不再显示为错误；真正的加载失败仍然照常提示。
- **供应商测试的第二步不再误标**。该步骤原本一律显示「② 本地协议转换」，但当供应商用原生协议、只是关闭了「保留工具结果中的媒体」时，它实际做的只是改写嵌套媒体，并非协议转换——格式下拉明明写着「原生」，这一步却显示协议转换，看起来像配错了。现在服务端会报告实际原因，两种情况分别显示：

  | 情况 | 第二步显示 |
  |---|---|
  | OpenAI 格式 | ② 本地协议转换 |
  | 原生格式 + 关闭媒体保留 | ② 本地处理工具结果媒体 |

  格式下拉旁也会补上说明，此前这一情况**没有任何地方解释过**。

## 说明

- 本次未改动 CLI 核心路径，也未改动发布流程。
- 自定义提示词存放在 `~/.claude/cc-haha/orchestration-prompts.json`。删除该文件即回到全部内置提示词。
- 新增的配置是纯增量：文件不存在时三个模式一律使用内置提示词。

# Code Council v0.5.57

> 本版本修复长会话中的流式断开恢复、“已思考”重复刷屏，以及自定义 Provider 模型推理强度为空的问题。

## 重点更新

### 流式连接恢复

- 空 SSE 流（`Stream ended without receiving any events`）在尚未产生输出、未执行工具且用户未取消时进入流级重试。
- 中间重试保持透明：成功恢复时不显示 API 错误；重试耗尽时只显示一次最终错误。
- Desktop 默认首事件等待调整为 120 秒，避免一次空流重试后长期停在 `attempt=1`。
- 保留用户取消和工具副作用边界：用户停止后不重试，已完成工具调用后不重放整个请求。

### “已思考”展示

- 每个用户轮次只保留一个 thinking 折叠入口；工具调用前后的多段思考合并到同一入口。
- 唤醒或重连时过滤已落盘的完整 thinking 重放，避免每次恢复都增加一组“已思考”。
- 空白 thinking 块不再生成空壳气泡。

### Provider 推理强度

- 修复预设槽位被替换后仍继承旧模型 capability 的问题。例如 `接口AI` Sonnet 槽改为 `gpt-5.6-terra` 后，不再错误继承 `SUPPORTED_CAPABILITIES=none`。
- 兼容模型恢复 Low / Medium / High / X-High / Max 推理强度选择。
- UI、REST 模型目录、WebSocket runtime effort 校验和 CLI 启动环境使用同一能力判定。
- 保留 K3 与兼容模型的 `xhigh` / `max` 档位；模型别名、命名空间及 `[1m]` 变体会正确匹配预设能力。

### 品牌与质量门

- Sidebar 测试与 `Code Council` 品牌保持一致。
- PR #148 的 server、desktop、provider contract、coverage、chat contract、persistence、agent-flow 和总质量门全部通过。
